# 匠石 LoCoMo 评测

入口为 `scripts/locomo_jshi_eval.py`。使用相邻 `../JShi` 的真实 `SubjectProcess`、
`CognitionSkill`、`MemoryShell`、REMS3 适配器与本仓记忆后端，不用另写的问答 Agent 代替核心。

## 第一轮范围

- 匠石是观察者，LoCoMo 两位说话人是其他人物；保持历史原话，不生成替代回复。
- 按历史时间逐话轮进入匠石经历台账，由记忆控制批量写入 REMS；测试结束强制封存残留。
- 默认木头人格的文本入口，使用其实际提示词、上下文组装和结构化回应契约。
- 对象身份由数据集说话人提供；查询涉及人物只从问题中显式出现的姓名匹配，不读取答案或证据。
- 入口采用默认回忆策略，不模拟语音 JEV 决策，也不增加主认知同轮补召回。
- 仅第一轮事件记忆基线：不运行后台人物长期经验维护，不让测试问题及回答回写长期记忆。
- 英文、观察者视角通过评测专用 system 叠加指令施加，生产提示词不改。
- 每题复制相同封存基线并重建核心现场，不共享问题、回答、写场或回忆强化状态。
- 英文嵌入 `BAAI/bge-small-en-v1.5`，384 维，查询前缀只加在查询侧。测试独立数据库和向量集合。
- 第一轮保留既有词面检索和阈值。第二轮可用 `--english-word-lexical` 仅启用英文整词覆盖；其余配置及评分定义保持不变。
- 小库未必触发 1000 事件以上的长期概率路径，不能据此验证大库遗忘/采样。

## 评分与隔离

运行前将参考答案拆为最少必要事实条目；保留主体、时间、否定、关系及可选答案条件。
条目文件和整体 SHA256 固定后才评分，数据、REMS/JShi 源码及运行器 SHA256 同时保存在 manifest。

每题保存真实核心 user 文本，从渲染后的【回忆】等节提取最终交付材料。
评分器同时得到核心实际使用的 `as_of` 时钟，便于解析回忆中的相对日期；该时钟不携带参考答案。
不能用后台事件原文替代摘要，也不能把 source_id 命中当作语义覆盖。
评分模型分别判断：

- `direct`：材料直接支持完整答案条目。
- `inferable`：材料中的必要前提齐全，允许短而明确的推导。
- `missing`：信息不足。
- `conflict`：是否另有未解决矛盾；必须引用矛盾材料。

程序拒绝缺失/重复条目、无依据的覆盖、非原文引用和没有推导的 `inferable`。
首次评分若引文格式无效，仅允许一次格式恢复：把实际交付回忆逐行编号，由评分器选择行号，
程序映射回原文；不存在的行号、布尔值或仍不合法的结果均拒绝，不重试有效的低分。
引文检查只能验证证据存在，不能保证语义判断正确；自动结果需要人工抽查。
标准答案、条目及证据标签只进入评测控制器和评分器，`answer_question` 不接收这些参数。

条目覆盖先逐题计算再宏平均；对抗题不计算覆盖，单独评价选项。
LoCoMo 第五类按官方输入构造，提供 `adversarial_answer` 干扰项与
`Not mentioned in the conversation` 两个选项，并解码字母选择后计分。
不能把原始第五类问题直接当作自由问答中的“无答案题”：部分原始问题实际存在其他真实答案。
“完整覆盖”还要求没有未解决矛盾。最终答案使用另一次调用独立评 `correct/partial/wrong`，
该调用不提供回忆材料，防止把“没找到所以合理拒答”误算成“答案正确”。程序拒绝
“有答案题拒答却满分”和“对抗题猜事实却满分”的矛盾评分。同时保留
LoCoMo 官方题型 F1（词干处理、逗号列表、拒答短语规则），两者不混成一个数字。

## 费用

所有付费调用经同一 `EvaluationLLM` 和 `runs/locomo_budget.jsonl`，只支持 `deepseek-flash`。
按 2026-10-15 查询到的高峰未缓存输入 ¥2/百万、输出 ¥8/百万保守估算；不是实际账单。
参考：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/

- 首轮累计提交额度默认 ¥10；任何运行的提交额度最大 ¥90，保留 ¥10 余量。
- 请求发出前预留 UTF-8 字节上界、消息封装余量与最大输出的费用；普通调用上限 4096 token，事件充实上限 16384 token，避免大缓冲封存被人为截断。
- 每笔预留立即持久化；API 返回 usage 后再结算；关闭 SDK 自动重试与思考模式。
- 缺失 usage、失败或超时保留整笔预留，阻止继续付费，等待核对。不能把失败自动当零费用。
- 无法取得实际 usage 时，可显式将整笔预留上限计入费用，并在账本标记 `usage_unknown`；
  不伪造 token 用量、不返还差额。中断写入库不用于评分，新建空库重跑。
- 文件锁阻止多个进程同时修改账本；本评测不并发调用付费 API。
- 所有输出路径在 `runs/`，不使用日常数据库。密钥只从环境变量或本仓 `.env` 读取，不写产物。

## 使用

在 `jshi-memory-test` 环境安装评测额外依赖 `nltk`。PorterStemmer 不需要下载 NLTK 语料。
评测只替换应用层时钟引用，不改变底层数据类型、网络时钟或模型运行库；
新封存事件的创建时间按回放会话时间校正，问题时间设为最后会话次日。

```powershell
python scripts/prepare_english_eval.py
python scripts/locomo_jshi_eval.py --out runs/locomo_first --questions 30 --budget 10
```

默认读取相邻 `../Locomo-Plus/data/locomo10.json`，使用第一组完整对话，抽样覆盖五种题型。
默认增加前三题的关闭回忆对照。固定 seed=42。不会修改 JShi 仓库。

第三轮使用 `--default-memory-triggers`：采用 JShi 默认字数、段数、时间及夜间触发条件，
每条真实历史发言入账后检查；采用同步投递保证确定顺序，没有模拟后台并发积压。
有限数据集结束时把剩余未投递内容提交一次，再封存残影；日志明确记录结束提交。
这与前两轮“人工约 3000 字符及会话末尾提交”有差别，比较时必须保留此边界。
主运行器现在拒绝后端返回含 errors 的批次，避免吞错后继续计分。

阶段可分别执行：`--phase prepare`、`ingest`、`finalize`、`answer`、`score`、`report`。
完整历史回放完成后保存检查点；`finalize` 可从该检查点继续残留封存，不重复回放历史。
已完成的条目、基线、回答与评分会跳过；未完成的历史或问题副本保留并拒绝自动重复执行，
避免未知费用和重复写入。源码/数据变化后使用新输出目录，费用账本继续累加。
`report` 阶段只读结果，不构建付费客户端。

结果：`report.md`、`summary.json`、`manifest.json`、`rubrics/`、`answers/`、`grades/`、
`api_audit.jsonl`；关闭回忆对照保存在 `control_answers/` 与 `control_grades/`。
完整真实 API 请求正文用于核对模板与泄漏，只保存消息和 usage，不保存认证头。
