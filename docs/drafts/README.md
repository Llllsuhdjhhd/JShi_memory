# 草稿箱

草稿箱用于某个模块进入方案设计、实现和调试阶段时，集中记录阶段性材料。它不是当前系统规格说明；草稿中的设想只有在代码实现并通过相应验证后，才应写入模块文档作为当前行为。

## 建议文件

每个进行中的模块议题单独建立一个草稿，例如 `recall-accessibility.md`。先复制 [_template.md](_template.md)，再按需补充：

- 模块、状态、关联代码和相关文档。
- 目标、现状证据、待解决问题和设计想法。
- 方案选择与取舍。
- 实施步骤、影响范围和回滚/迁移考虑。
- 验证场景、测试结果、调试记录和未决问题。

## 状态流转

推荐状态：`讨论中` → `方案已定` → `实现中` → `验证中` → `完成`。完成后把稳定结论同步到模块文档；草稿可保留决策过程。若方案取消，记录原因并标为 `已搁置`，不要把未实施内容写成现行功能。
