# 回忆：可及性、时间衰减与重复强化

## 状态

- 状态：讨论中
- 更新日期：2026-09-26
- 关联代码：`src/rems/recall/pipeline.py`、`src/rems/services/event_service.py`、`src/rems/config.py`
- 关联模块文档：[回忆](../recall.md)

## 目标

验证情绪、时间和重复回忆如何影响事件进入长期语义搜索的机会；保留“近期保底 + 长期概率通道”的总体方向，同时避免可及性吞掉查询相关性。

## 当前实现与证据

- 最新 80 个符合主体/对象/时间条件的事件进入近期语义池，近期语义 `top_k` 默认 40。
- 更早的事件先按概率抽样，再进入长期语义搜索。概率由 `event_fatigue × forgetting_factor × 时间半衰衰减` 映射得到，默认半衰期 60 天、概率下限 0.05。
- 查询相关度是语义分和词面分的较大值；对象角色权重再乘入排序分。可及性只在相关度接近的排序组内改序。
- 语义池的概率抽样不限制词面通道遍历事件，因此当前“长期概率”不是所有检索方式共用的全局闸门。
- 事件封装时，`activation_energy` 取情绪 arousal，并由 `initial_forgetting_factor()` 映射为初始遗忘因子：`2 ** (gain * (activation_energy - 0.5))`，默认 `gain=2.0`。
- 只有进入最终回忆结果的封存事件才会强化：遗忘因子默认乘以 1.15，上限 3.0；一次查询同一事件最多强化一次。
- 时间过滤使用 `occurred_at`，而近期排序和当前年龄衰减使用 `create_time`。发生时间与录入时间可能不同，需要纳入验证。

## 想法与待决问题

1. 近期窗口按事件条数还是按自然时间长度更符合匠石的使用节奏？
2. 年龄衰减应继续基于创建时间，还是改用 `occurred_at` 并在缺失时回退？
3. 目前情绪通过 arousal 影响初始因子。是否需要把情绪类型、正负效价或事件的重要性也纳入，可及性？先明确数据和评价标准再设计，避免重复计权。
4. 重复强化目前按“最终交回”计次。是否需要时间间隔、查询有效性或强化衰减，以免高频重复提问造成偏置？
5. 词面通道是否也应受长期概率控制？如果是，要先评估专名/数字查询漏召回的代价。
6. 概率下限保证偶然性，但大量历史事件时仍可能产生较大候选池；需评估延迟和抽样稳定性。

## 方案方向（待讨论）

保留两阶段职责：近期路径负责对近事提供稳定机会；长期路径在相似度检索前通过可及性概率抽样。检索后仍由查询相关度决定主要顺序，只在接近候选间让可及性发挥次级作用。情绪、时间和重复强化先作为可及性因子的构成/更新来源来验证，不直接乘进向量相似度。

暂不在本草稿中定新的公式或参数。先用可控事件集对情绪档位、事件年龄、重复命中次数、查询相关度和对象角色构成组合场景，记录命中率、排序变化、概率分布及检索耗时。
