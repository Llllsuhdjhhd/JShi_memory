# 220 投递策略（30 侧批次冲刷）

> 210 的子文档（区间 220–400）｜状态：草稿

## 1. 定位

- 记忆摄入的**触发时机**由 30 侧决定：16 经历段累积 → `build_memory_batch`（按阈值取未投递段）→ `ingest_batch`；
- 本文件定义冲刷策略与参数；后端 `ingest_batch` 只负责接收（有序处理、失败重试、`stored_marks` 游标），行为不随策略变化；
- 所有参数可配置（默认值见下）。

## 2. 触发机制（参数化）

### 2.1 按长度（累积触发）

| 参数 | 默认 | 说明 |
|------|------|------|
| `flush_max_chars` | 2000 | 未投递经历段 text 总字数 ≥ 阈值 → 冲刷一批 |
| `flush_max_segments` | 20 | 段数 ≥ 阈值 → 冲刷（防长期不触发） |
| `flush_max_idle_seconds` | 600 | 距上次冲刷超过该秒数 → 冲刷（保证记忆不过期） |

### 2.2 按空闲 / 时段

| 参数 | 默认 | 说明 |
|------|------|------|
| `flush_on_idle_seconds` | 1800 | 无新经历超过该秒数 → 冲刷全部未投递段 |
| `flush_night_window` | "00:00-06:00" | 处于配置时段 → 冲刷全部未投递段（深夜沉淀） |

- 空闲 / 夜间冲刷是未来 `consolidate` / `dream` 后台端口的自然挂载点（本轮占位）。

## 3. 冲刷行为

- `MemoryBatch`：`subject_id` + `experiences`（**有序 = 经历先后**，对话轮次不乱序）；
- 只取"未投递段"（30 侧维护 `memory_start` 游标之后的区段）；
- 成功：凭 `stored_marks`（segment_id → 事件 id 列表）推进游标、更新台账；
- 失败：未投递区保留原文，批次可重试，**不丢段**；
- 参数全部可配置（环境变量 / 配置），默认值如上。

## 4. 与其他模块的关系

| 模块 | 关系 |
|------|------|
| 210 输入协议 | `MemoryBatch` 结构、`stored_marks` 语义 |
| 810 存储 | `stored_marks` 台账表（30 侧凭它推进游标） |
| 1010 回忆 | `consolidate` / `dream` 占位端口未来可承接空闲冲刷后的整理 |

## 5. 验收标准

- 文档评审通过；
- 30 侧按参数触发冲刷，后端 `ingest_batch` 行为不变（批量、有序、失败隔离已有测试覆盖）。

## 6. 30 侧落地清单

### 6.1 命名同步（契约字段，两端必须一致）

- `MemoryInput` → **`MemoryExperience`**；`MemoryBatch.inputs` → **`experiences`**；`input_id` → **`segment_id`**；
- 涉及位置：30 侧 `build_memory_batch` 构造端、投递调用、`stored_marks` 游标/台账读取、
  契约文档（`doc/design/09-记忆系统.md` 按契约重写）、以及 JShi 的 `InProcessMemoryBackend`
  （实现同一端口形状，字段名一致，保证可替换）。

### 6.2 投递流程（对照 §2–§3）

1. **收集**：16 经历段（text_raw + objects + source_ids，原文不改写）→ 07 收尾 → 30 `run_once`；
2. **触发**（参数可配）：按长度（字符/段数/距上次冲刷超时）或按空闲/深夜时段；
3. **组批**：`build_memory_batch` 取 `memory_start` 游标之后的未投递段，构造
   `MemoryBatch(subject_id, experiences=[MemoryExperience(...)])`，**保持经历先后顺序**；
4. **投递**：`ingest_batch(batch) -> BackendIngestResult`；
5. **游标/台账**：凭 `result.stored_marks`（segment_id → 事件 id 列表）推进 `memory_start`、更新台账；
6. **失败**：未投递区保留原文，批次可重试，不丢段；
7. **origin 映射**：`output_kind`（external_input / subject_reply / subject_state / subject_silent → external；internal → internal）。
