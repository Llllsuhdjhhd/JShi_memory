## 0. 总览：两条端口

```mermaid
flowchart LR
    J30["匠石 30 侧<br/>经历段 / 批次冲刷"] -->|"MemoryBatch"| ING["REMSPipeline.ingest_batch"]
    ING --> META["MetabolismService<br/>残影 / 未完成库 / 边界切分"]
    META --> EV["EventService.seal_event<br/>摘要 / 情感 / 角色列表"]
    EV --> ROLE["RoleService<br/>对象分级白描"]
    EV --> POR["PortraitService<br/>人物肖像"]
    ING --> DB[("SQLite<br/>events / unclosed_events / shadow<br/>stored_marks / object_memory_entries<br/>white_painting_entries / portraits")]
    ING --> VDB[("Qdrant<br/>事件向量")]
    ING -->|"BackendIngestResult<br/>stored_marks"| J30
    J03["匠石 03 / 05"] -->|"query"| REC["REMSPipeline.recall"]
    REC --> RP["RecallPipeline<br/>多路召回 / RRF / 预算"]
    RP --> DB
    RP --> VDB
    REC -->|"tuple RecalledFragment"| J03
    J30 -.->|"consolidate / dream<br/>本轮占位"| ING
```

**读图要点**

- 写入与回忆是**两个互不耦合的端口**（design/210 §4）；回忆不写记忆单元，唯一写操作是"记忆恢复"。
- 后端的内部缓冲（残影 / 未完成事件）不整体跨端口；`unclosed_count` 只反映缓冲规模。
- `consolidate` / `dream` 为占位端口，本轮不实现（做梦代码保留不动）。

## 1. 写入：批次级 `ingest_batch`

```mermaid
flowchart TD
    A["batch: MemoryBatch<br/>subject_id + experiences 有序"] --> B["逐条检查 text 是否为空白"]
    B -->|"空白"| E1["errors += segment ?: empty text<br/>该段跳过，不算致命"]
    B -->|"有内容"| C["valid 列表"]
    C --> D["整批合并为一段输入<br/>combined = 各段 text 以空行连接<br/>merged_objects / merged_sources 取并集<br/>sub_segments 记录段级 text + objects + interlocutor"]
    D --> F["构造批级 MemoryExperience<br/>segment_id = 各段 id 用 + 连接<br/>interlocutor = 首个非空段说话对象<br/>origin = 首段 origin"]
    F --> G["MetabolismService.process_input"]
    G --> H["返回 sealed 事件列表<br/>注意：已含本轮被中断封存的旧未完成"]
    H --> I["逐事件汇总<br/>sealed_event_ids<br/>role_ids = 非主体对象<br/>recall_pipeline.index_event 写向量"]
    I --> J["stored_marks 归属<br/>事件的 content_raw 与各段做句子级重叠匹配<br/>命中多段则多段都记；全不命中回退到整批 key"]
    J --> K["interlocutor 回填：命中段里第一个有归属的段对象<br/>否则回退批级；event_repo.save 重存"]
    K --> L["portrait_service.note_event<br/>为事件涉及对象各生成一条人物摘要"]
    L --> M["stored_marks_repo.save<br/>每个 segment 一行台账"]
    M --> N["unclosed_count = len(meta_repo.get_unclosed_events())"]
    N --> O["BackendIngestResult"]
    E1 --> B
```

**读图要点**

- **整批合并**：一批经历合成一次代谢，不是"一段一次"，与 rems3 整批语义对齐；`stored_marks` 靠内容重叠把事件**归回**各 `segment_id`（一个事件可命中多段）。
- `stored_marks` 语义（design/610 §6）：封存几个填几个；本轮完全没封存则**不写该项**、不算错误。
- 失败隔离是**段级**的：空文本进 `errors`；整批代谢异常也进 `errors`，不抛穿调用方。
- `index_event`、`note_event`、`stored_marks` 保存都各自 try/except 进 `errors`，不阻断其余步骤。

## 2. 写入：代谢内部（残影 / 未完成生命周期）

```mermaid
flowchart TD
    A["process_input(raw_input, memory)"] --> B{"len > len_msg ?"}
    B -->|"是"| W["仅告警，边界检测照跑"]
    B --> C["unclosed = repo.get_unclosed_events()<br/>now = memory.occurred_at 或当前时刻"]
    W --> C
    C --> D{"force_save ?"}
    D -->|"是"| FS["_force_save_all<br/>残影 + 输入合并封存<br/>再逐条封存未完成 + 清空虚影"]
    D -->|"否"| E["_seal_abandoned_unclosed<br/>单条 UC 字数 ≥ unclosed_char_limit<br/>或 半限×闲置≥3天 / 闲置≥7天<br/>说话人更换不封存"]
    E -->|"封存"| E1["_seal_unclosed_as_event<br/>按原文封存，不要求语义闭环<br/>并从缓冲删除"]
    E --> F["shadow = join(剩余 UC.merged_content)"]
    E1 --> F
    FS --> Z["返回 abandoned + sealed"]
    F --> G["BoundaryDetectionSkill.detect<br/>原文按句子编号，模型只回序号列表"]
    G --> H["规则评估器 BoundaryForceThresholdEvaluator"]
    H --> I{"报告 ok ?"}
    I -->|"否"| J["OverlongUCSplitRemediator<br/>80/20 分裂修复，只修一次、修后不再评估"]
    I -->|"是"| K["_apply_boundary_result"]
    J --> K
    K --> L["封存事件 + 清理并重建未完成库 + 更新残影"]
    L --> M["_maybe_shadow_compact<br/>碎片数超阈值时压缩残影"]
    M --> N["_check_physical_redline"]
    N --> N1{"残影 + 未完成 > physical_redline ?"}
    N1 -->|"是"| N2["超 force_threshold 的 UC 强制封存<br/>24 小时未续写的 UC 也封存<br/>残影仍超 safe_watermark 则截尾保留"]
    N1 -->|"否"| Z
    N2 --> Z
```

**读图要点**

- **封存在边界检测之前**：先按时间 / 说话人判定"旧挂起条目已经结束"，避免旧残影被拼进新话题（design/610 定稿 8）。
- 未完成库的重建规则：**残影 = 现有未完成条目的拼接**；模型没在 `new_unclosed` 里重新声明的旧条目按 trace decay 丢弃（防跨轮重复持有）。
- 三处"结束"语义并存：`force_save`（手动 / 兜底）、**中断封存**（时间 / 场景）、物理红线兜底。
- `_check_physical_redline` 是最后一道防线，即使认知层（评估 → 修复）失败也不允许缓冲无限膨胀。

## 3. 写入：边界结果落地 `_apply_boundary_result`

```mermaid
flowchart TD
    A["BoundaryResult<br/>completed_events + new_unclosed"] --> B["遍历 completed_events"]
    B --> C{"continuation_of 命中旧 UC ?"}
    C -->|"是"| D["content = 旧 UC 原文 + 本片段<br/>继承该 UC 的 split_prefix_event_ids<br/>删除该 UC"]
    C -->|"否"| E["content = 片段原文"]
    D --> F["EventService.seal_event"]
    E --> F
    F --> G{"片段标了 is_split_prefix ?"}
    G -->|"是"| H["登记 split_id → 新事件 id"]
    G --> I{"事件继承了前缀链 ?"}
    I -->|"是"| J["给每个前缀事件 append_split_successor"]
    H --> K
    I --> K["删除所有未被 continuation_of 命中的旧 UC<br/>无主碎屑按 trace decay 丢弃"]
    K --> L["遍历 new_unclosed 新建 UnclosedEvent<br/>oversized 标记 / split_id 对应前缀 / interlocutor 取批级"]
    L --> M["repo.update_shadow<br/>残影 = join(未完成条目原文)"]
```

**读图要点**

- 80/20 分裂链路是**双向**的：前缀事件记 `split_successor_event_ids`，尾段闭环时把 `split_prefix_event_ids` 继承给新事件；回忆时锚点路会把这串前缀拉回来。
- `oversized` 只是**审计标记**，不再触发强制封存（旧版"越阈值就 force-seal"已废弃）。

## 4. 写入：事件封装 `EventService.seal_event`

```mermaid
flowchart TD
    A["seal_event(content_raw, objects, subject_id, source_ids, occurred_at, origin ...)"] --> B{"len > len_msg ?"}
    B -->|"是"| C["截断到 len_msg 并告警"]
    B --> D["_compute_budget<br/>短文本宽恕 + L1–L10 摘要预算<br/>快照 L1–L3 / 白描 / 装饰预算"]
    C --> D
    D --> E["EventEnrichmentSkill.enrich<br/>memory 模式：summaries + 事件级主体情感 + 对象分级白描 + keywords/location"]
    E --> F["role_list = 主体恒在 + objects 映射表各对象<br/>不抽角色、不建档；对象无情感、无等级"]
    F --> G{"enable_decoration ?"}
    G -->|"是"| H["LLM 生成 decoration"]
    G --> I["compression_ratio = sum_len / raw_len"]
    H --> I
    I --> J["构造并落 Event<br/>content_raw 原文不改写<br/>subject_id / source_ids / occurred_at<br/>input_id = 批级 segment_id / origin"]
    J --> K["activation_energy = arousal<br/>EMAEvolver 演化"]
    K --> L["forgetting_factor = 2^(gain × (AE − 0.5))<br/>中性 0.5 → 1.0"]
    L --> M{"任一条目 arousal > ptsd 阈值 ?"}
    M -->|"是"| N["ptsd_immune = True"]
    M --> O["event_repo.save"]
    N --> O
    O --> P["逐对象 append_object_white_painting<br/>l1_mention / l2_interaction / l3_decision，事件关联，无情感"]
    P --> Q["返回 Event"]
```

**读图要点**

- **原文保全**是不变量：`content_raw` 只做长度截断，不改写、不归一化（单事件场景 `content_raw == 输入 text`）。
- **主体恒在**：`role_list[0]` 恒为主体（`role_id = subject_id`，`is_subject=True`，importance S）；对象按 `objects` 映射表挂载，与文本是否提及无关；`objects` 空即"主体记忆"，同样合法。
- 摘要保留 L1–L10 多级衰减与熔断（design/610 定稿 2），对外至少保证 L1 可用。

## 5. 回忆：`recall` 管线

```mermaid
flowchart TD
    A["recall(subject_id, query, object_id, level, limit, anchor_event_ids)"] --> B["query 归一化；为空直接返回空"]
    B --> C["RuleIntentClassifier<br/>fact / entity / emotion 软混合"]
    C --> C1{"object_id 为空且意图解出对象 ?"}
    C1 -->|"是"| C2["用意图对象作焦点对象"]
    C --> D["候选事件 = list_all(exclude_tombstoned) 且 subject_id 匹配"]
    C2 --> D
    D --> E["未完成路：_unclosed_fragments<br/>同一 interlocutor 优先 90 分<br/>无焦点对象时按查询 bigram 重叠 40×(0.5+jac)<br/>焦点对象已定则不拉其他对象的挂起条目"]
    E --> F{"事件与未完成都空 ?"}
    F -->|"是"| Z0["返回空元组"]
    F --> G["多路候选生成"]
    G --> G1["语义路：query 向量 → Qdrant top_k<br/>payload 过滤 subject_id / object_ids"]
    G --> G2["词法路：bigram Jaccard 排序"]
    G --> G3["对象路：事件 role_list 命中 → 回退 object_memory_entries"]
    G --> G4["时间路：recency 窗口内按 create_time 降序"]
    G --> G5["锚点路：anchor_event_ids + split 前缀链展开"]
    G1 --> H["逐条打分"]
    G2 --> H
    G3 --> H
    G4 --> H
    G5 --> H
    H --> I["eff = event_fatigue × forgetting_factor × 0.5^(age_days / 60)"]
    I --> J{"eff < silence_threshold 0.02 ?"}
    J -->|"是"| Z1["静默：不进回忆，但原文不删"]
    J --> K["rrf = Σ 各命中通道 1/(rrf_k + rank)"]
    K --> L["score = rrf × eff^alpha<br/>× 情感调制 valence 匹配 ±mood_beta<br/>× 对象归属软纠偏 1.15 / 0.90"]
    L --> M["按分数降序取 top_k"]
    M --> N{"装配了精排器 ?"}
    N -->|"是"| N1["rerank 对 top_k 重排"]
    N -->|"否"| O["逐条组装 RecalledFragment"]
    N1 --> O
    O --> P["text = content_raw 原文<br/>content = 按 level 选出的档位摘要<br/>object_id / interlocutor / source_ids / score / occurred_at"]
    P --> Q["记忆恢复：forgetting_factor = min(ff × 1.15, 3.0)"]
    Q --> R["apply_recall_budget 预算分配 + 肖像同场"]
    R --> S["_record_recall_trace 落 recall_traces<br/>仅观测，可配开关关闭"]
    S --> T["返回 tuple RecalledFragment"]
```

**读图要点**

- 未完成条目以 `kind="unclosed"` **直接排在片段列表最前**（`summary_level="raw"`，`content` 即挂起原文），这是本轮在制品的改动。
- **软纠偏有界**：只乘 1.15 / 0.90，不硬删；焦点对象或条目归属缺一即乘 1.0（退化为纯主题相关）。
- `score` 的四个因子互相独立：通道融合（RRF）、遗忘/疲态、情感、对象归属。
- 检索文本不是原文，而是 `L1 摘要 + 对象 id + 地点`（富化嵌入，design/1010 §2.4）；原文只在展示时给出。

## 6. 回忆：预算分配与肖像同场（1010 §8.5）

```mermaid
flowchart TD
    A["回忆片段 + 对话人肖像条目 score = 100"] --> B["按 score 降序排序"]
    B --> C["6 级预算<br/>L1 = 100 字，逐级 ×2，L6 = 3200 字<br/>总预算 = recall_budget_chars 或 physical_redline"]
    C --> D["逐条贪心：从最长级往下找第一个装得下的档位<br/>use = min(档位上限, 内容长度)"]
    D --> E{"装得下 ?"}
    E -->|"否"| F["丢弃该条及其后所有条目"]
    E -->|"是"| G["扣减 remaining，记录 level / budget / used"]
    G --> H["content 截断到 used"]
    H --> I["写回 summary_level = 所选档位"]
    I --> D
```

**读图要点**

- 口径统一：**L1 = 最短/最简，级数越高越详细**（与人物肖像一致）。
- 由于"能装最高级就装最高级"，短条目在小预算下也会被标成高档位（例如 L6）——这正是 `tests/unit/test_recall_trace.py::test_recall_persists_query_and_items` 当前失败的原因：测试仍期望 `L1`。

## 7. 人物肖像生成（1010 §8.4）

```mermaid
flowchart TD
    A["事件封存完成"] --> B["_portrait_objects = interlocutor ∪ 非主体 role_list"]
    B --> C["逐对象 generate_object_summary"]
    C --> D{"摘要非空 ?"}
    D -->|"否"| E["跳过该对象"]
    D -->|"是"| F["portrait_summaries 落库 incorporated = False"]

    G -->|"否"| H["留在缓冲，等下次累计"]
    G -->|"是"| I["update_portrait"]
    I --> J["总长 = 已有 total_content_len + 待并入<br/>compute_level_budgets：L1 = max(100, 总长 / 2^9)<br/>Lk = L1 × 2^(k−1)，某级超总长即停，最多 10 级"]
    J --> K{"compose_mode = auto ?"}
    K -->|"总长 ≤ 1/6 上下文"| L["full：用全部摘要重建多级"]
    K -->|"否则"| M["incremental：已有最长级 + 新摘要"]
    K -->|"显式配置"| N["按配置走 full 或 incremental"]

```

**读图要点**

- 肖像按**对象各一份**，彼此独立；`note_event` 的调用注释写"后台 / 并行，不阻塞 ingest"，实现上是**同进程同步调用**（LLM 在 ingest 请求路径上）。
- 两种疲态不共用：事件用 `event_fatigue`（只看整体负担），肖像用 `portrait_fatigue`（整体 + 对象合成）。

## 8. 遗忘与记忆恢复生命周期

```mermaid
flowchart LR
    A["封存：arousal → activation_energy"] --> B["初始 forgetting_factor = 2^(2.0 × (AE − 0.5))"]
    B --> C["时间衰减：0.5^(age_days / 60)"]
    C --> D["召回打分 eff = event_fatigue × ff × 衰减"]
    D --> E{"eff < 0.02 ?"}
    E -->|"是"| F["静默：不进回忆<br/>只降可见性，不删原文"]
    E -->|"否"| G["可被召回"]
    G --> H["被召回 → ff = min(ff × 1.15, 3.0)"]
    H --> C
    D --> I["上限 recall_forgetting_factor_cap = 3.0"]
```

**读图要点**

- 情感只属主体且为事件级；对象无情感（design/410）。
- 强化是**温和且有上限**的：1.15 倍 / 上限 3.0，避免高频命中事件变成"永不遗忘"（历史上 1.5 倍 / 300 的问题）。
- `ptsd_immune` 事件走 `w_i = cap` 的免死路径（旧权重推导链，现记忆路径主要用 `forgetting_factor`）。

## 10. 一次 `ingest_batch` 的调用顺序

```mermaid
sequenceDiagram

    participant P as REMSPipeline
    participant M as MetabolismService
    participant B as BoundaryDetectionSkill
    participant E as EventService
    participant R as 仓储 / 向量库
    J30->>P: ingest_batch(MemoryBatch)
    P->>P: 过滤空文本 / 整批合并 / 建 sub_segments
    P->>M: process_input(combined, memory)
    M->>R: get_unclosed_events
    M->>M: _seal_abandoned_unclosed 中断封存
    M->>B: detect(shadow, input, unclosed)
    B-->>M: BoundaryResult
    M->>M: 评估 + 必要时 80/20 修复
    loop 每条 completed_event
        M->>E: seal_event(content)
        E->>E: 预算 / enrichment / 主体+对象角色列表

    M-->>P: sealed 列表
    loop 每个封存事件
        P->>R: index_event 写向量
        P->>R: 回填 interlocutor 并重存
        P->>R: portrait note_event 摘要入库
    end
    P->>R: stored_marks 台账
    P-->>J30: BackendIngestResult
```

## 11. 画图时发现的不一致（建议后续拍板）

1. **说话人更换不再作为封存条件**（2026-09-20 已定）：未完成封存仅看单条字数上限与闲置规则；
   旧的 `unclosed_interlocutor_break_seal` 默认关闭且逻辑已移除。
2. **物理红线 / 陈旧封存走的是旧角色抽取路径**：`_check_physical_redline` 与 `_forget_stale_unclosed` 调
   `_seal_unclosed_as_event(memory=None, ...)`，于是 `seal_event` 走 `memory_mode = False` 分支，会调
   `RoleService.resolve_and_register` 抽角色、注册 `ROL-*`，绕过"主体恒在 + 01 对象映射表"，也与"不建角色系统"冲突。
