# 回忆实例的原因分析

本次只读第二轮正式结果、只读数据库和实际检索轨迹，没有发起新的模型请求或修改评测分数。
证据产物为 `runs/locomo_round2_clean/failure_diagnostics.json`，可通过
`python scripts/inspect_locomo_recall_failures.py` 重新导出。

## 1. 已找到正确材料，组装时却没有交付

q16 问 Melanie 何时报名陶艺课：

- 检索第 1 项是一段 6048 字符的混合事件，主要是徒步、画画、社区、陶艺盘子等。
  词面分 1，最终分 0.3；语义信号为 0，表示本次语义通道未给它提供分数，不能据此断言真实相似度为零。
- 第 2 项就是正确报名事件，摘要开头明确写 signed up for a pottery class yesterday，
  语义分 0.773075，最终分 0.297981，摘要 946 字符。
- 第 3 项是同一正确事件的对象事实，484 字符。
- 核心最后只收到第一段长材料，最终答“不知道何时报名”。正确事件出现在 assembly skipped 列表。

原因有两层：词面满分可让长材料压过语义匹配更明确的材料；核心组装预算默认 1500 字符，
但算法只检查“放入前是否还有预算”，直接收下整个片段，再扣除全部长度。
因此 6048 字符的第一段能整体放入，然后挡住后面的正确材料。

这不是靠单纯增大召回 top-k 能解决的：正确事件已经在第 2 位。
后端按自身预算选摘要，核心又按另一预算整段收取，两个预算环节没有协调选级。

## 2. 重复材料占位，多条目问题变成单条目回答

q24 标准需要 running 和 pottery。
后端前 3 项是同一次跑步经历的对象事实、事件摘要、另一事件 ID 下的重复事件摘要。
核心收到前两段同主题跑步记忆，再加一段跑步自我照顾经历，合计约 1943 字符。
陶艺摘要已在第 13 项，语义分 0.645403，最终分 0.231121，但组装时被跳过。

数据库共 94 个事件，逐字相同的 content_raw 只有 81 种，存在 11 组完全重复原文。
其中跑步事件和红蓝画事件各有两个不同 ID。
核心 MemorySource 只按 event_id 去重，无法合并跨 ID 的相同经历；
同 ID 的 event/fact 又先在后端分别消耗预算，再由上层去重，预算利用也存在损失。

目前排序优化的是每条材料相关性，没有保障“第二条材料应补充第一条没有的信息”。
多放几段相似内容，不等于找齐多个必要事实。
已证实重复记录存在；重复产生于哪个具体写入分支，还需要单独追踪，不能仅据快照归因。

## 3. 词面满分与分数封顶，抹平了具体事件差异

q116 问“艺术展那幅画的灵感”，真正材料是到 LGBTQ center 后画树与太阳，表达 unity and strength。
实际交付的前两段却是另一幅红蓝画，解释性别二元与自我接纳。

正确的短事件只需 348 字符，位于后端第 7 项：语义分 0.735472，高于第 1 项的 0.715173，
但两者词面分都为 1，合成相关度均封顶，乘对象权重后均为 0.3。
同分时按材料类型、可及性等继续排，正确材料的语义优势消失；
第 1、2 项又是同一幅红蓝画的重复来源，提前用完交付预算。

这说明英文整词修复解决了字符片段误匹配，却仍不能判断
“出现 Caroline、painting、inspired”是否真正对应“art show 的那一幅”。
需要保留事件限定关系与最终排序的区分度，不能只算词集合覆盖。

## 4. 日期锚点在交付时丢失，部分写入时间字段也不完整

正确报名事件的 create_time 为 2023-07-03 13:36，正文含 yesterday，
但 occurred_at 为空。全库 94 个事件中仅 3 个填有 occurred_at，
回忆用 occurred_at or create_time 作为兜底时间。
核心提示词又把时间转换成“2个月前”等粗粒度标签，没有交付原始年月日。

即便正确报名摘要进入回忆，仅凭“2个月前 + yesterday”也不能可靠恢复 2023-07-02。
q28/q29 的 last Friday 同样缺少原始会话日期。评分器曾因此推错日期，已另存阅读复核修正。

因此要区分事件发生时间、原始会话日期和封存/创建时间。
精确问答应交付可核对的时间锚点；不能把封存时间一概当成真实发生日期。

## 5. 人物相关不等于事实属于该人物

q163 问 Melanie 的心理咨询方向。
交付回忆标题为（Melanie），正文却明确写 Caroline 想从事心理咨询、帮助跨性别人群。
该事件确实与 Melanie 有关，因为她参与对话，但职业愿望属于 Caroline。
核心最后选了将 Caroline 职业愿望归到 Melanie 的干扰项。

检索按“参与/涉及人物”筛选，不能保证每句事实的主体与问题人物相同。
展示名有诱导归属风险；核心也没有遵循正文中已有的人物区分。
此例是人物关系检索与最终回答共同失误，不能只归因于提示词标题。

另观察到部分未交付摘要写成 Last weekend JShi joined...、JShi's kids，
说明观察者身份叠加指令没有完全阻止写入时主体漂移。
这些坏摘要不应被当作事实，但尚不能证明它们是本轮各错题的直接原因。

## 6. 找到部分线索后，核心仍可能过度拒答

q19 中回忆明确说孩子 excited learning about nature，回答却说
“已有记忆提到他们兴奋地学习自然，但没有说他们喜欢什么”。
自然这一条至少有可推导支持，恐龙则确实缺失。
恐龙摘要在库中完整保留，并已进入后端第 15 项，但在组装时跳过。

所以这题同时有两个问题：回忆没有交付全部条目；核心又把部分可用证据整体拒掉。
q12 首轮材料含 ten years ago 却仍拒答，第二轮在同样有该事实时答对，
也说明最终回答存在波动，不能把所有变化算作检索改善。

## 建议的改进顺序

1. 先修交付预算与重复占位：为核心实际可用预算选合适长度，合并同来源/同内容重复事件，
   验证 q16 第 2 位的正确报名事实、q116 的 348 字符正确事件能否真正进入核心。
2. 再修排序的分数饱和与证据互补：保留语义区分，关注人物、具体事件及关系限定，
   对列表题在有限预算里覆盖不同线索。不能根据标准答案指导检索。
3. 补齐原始日期、事实主体的结构化交付，再约束核心对部分已知信息作答。
   单独验证时间题、人物混淆和过度拒答，避免一次改动后无法解释来源。

这些是基于具体轨迹的诊断与改进假设，尚未实施新一轮修复或宣称新的收益。
