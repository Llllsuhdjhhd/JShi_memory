# V2、V3 的区别和答错原因复核

本次只分析已有实际运行记录，没有修改记忆代码、重跑模型或覆盖原始评分。

## 两个编号是什么意思

V2、V3 是同一轮开发中的两次实验编号，不是模型版本，也不是记忆 L2、L3。

两者均使用轻量小事件、90/365/1095 天多阶段提炼、L1 默认三分之一保留比例、L0 向量索引、英文 BGE 和 deepseek-flash；使用同一历史、同一 30 题、同一冻结评分条目和真实 JShi 核心。

| 项目 | V2 | V3 |
|---|---|---|
| 原始小事件 | 复用首次轻量写入的 197 条 | 修复来源重投后，从空库重新形成 179 条 |
| 后台提炼 | 修复分组 JSON 解析后，继续完成到龄提炼 | 从新小事件库重新完整提炼 |
| 上层事件 | 28 条 | 28 条，分组及内容并不相同 |
| 同源正文包含式重复 | 4 组 | 0 组 |
| 自动答对 | 15/30 | 11/30 |
| 阅读复核后答对 | 16/30 | 11/30 |

因此，V3 不是在 V2 固定记忆库上仅删除重复。事件边界、聚合组、摘要、回答均重新生成，不能把差异全部归因于去重，也不能直接据此选择“更好的版本”。V2 的 q16 另有相对日期语义复核，所以自动成绩与阅读复核成绩不同。

## 长度修复的具体证据

q47 的父事件 L0 为 901 字符，L1 预算为 300 字符。初次模型输出包含完整的朋友、家人、导师名单，但超长。长度修复模型返回的前几个事实为：

1. 研究领养机构：42 字符。
2. 想建立家庭、给孩子有爱的家：92 字符。
3. 一段机构标识图片描述：128 字符。
4. 觉得希望和乐观：74 字符。
5. 朋友、家人、导师给她支持：110 字符。

程序按顺序装入完整句。前三句连同分隔空格用了 264 字符，只剩 36 字符；后面的支持者名单放不下，被整句舍弃。这里没有从一句话中间硬截，但确实删除了整个事实。

另一个实现缺口是修复提示要求单条事实最多 80 字符，返回的 92、128、110 字符事实却仍被当前装入逻辑接收，没有严格检查这个子预算。模型排序没有优先保名单，程序也没有按来源覆盖约束重新分配空间，两者共同导致损失。

所以，“L1 已满足三分之一长度”与“正确完成了记忆压缩”不能画等号。当前检查证明长度、来源拼接和发布事务正确，还没有保证每个被隐藏的小事件在 L1 中留有代表事实。

## q184 为什么不能算记忆变差

实际题目：Caroline 玩什么乐器？选项只有 `(a) 未提及` 和 `(b) 单簧管和小提琴`。

实际历史及交付回忆：Caroline 说主要弹吉他，而且弹原声吉他约五年。

V2：选 `(a) 未提及`，同时解释她弹吉他，选项不匹配，因此正式评分正确。

V3：说两个选项都不正确，她弹原声吉他，因此正式评分错误。

这说明当前把对抗问题包装成“错误事实选项/未提及”的方式，在真实历史存在第三个正确答案时，会把遵守选项协议与真实事实回答混在一起。应保留正式 11/30 成绩，并将本题单列为协议不匹配；不能称其为事实猜测或记忆退步。此前报告对这题没有作充分区分，本次补充纠正解释，不覆盖原始成绩。

## 我的判断与处理顺序

最优先修提炼：完整保留 L0 不等于后续还能用到底层细节；隐藏来源后，L1 中整件事情消失，会让多个问题同时失去依据。应约束每个来源的代表事实和预算分配，检查名单、数字、行为与时间，严格执行每条事实的长度限制。三分之一暂可作为总预算，先修预算如何分配，而不是先提高比例。

其次检查从候选到实际交付的排序和预算。正确材料进入候选但核心未收到，不能靠更强的回答模型补救；同主题的别次事件也不能代替目标事件。

再区分直接事实、合理推断、反事实和对抗题的回答口径，单列数据集与强制选项的不一致。由此才能判断模型能力，而不是把所有正式判错都归因于 Flash。

证据保存在 `runs/locomo_round5_staged_v2/`、`runs/locomo_round5_staged_v3/` 的原始答案、回忆轨迹、评分及 API 输出中。此次复核没有新增付费调用。
