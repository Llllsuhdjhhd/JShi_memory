# 按经历年龄分阶段提炼记忆

本分支实现已经确认的流程：近期闭合事件只保存原文；经历到龄后，后台选择连续事件进行提炼；第一次提炼生成摘要、主体情绪和对象事实；第二次只从上一阶段的 L1 再提炼，此后不再提炼。普通检索只读取尚未被上层吸收的事件。命中上层事件后，相似度达到门槛的第一层原文附在同一条结果里。

## 形成轻量事件

默认开启 `memory_refinement.enabled`。JShi 原有投递条件保持不变：投递批次进入记忆模块后，由专用小事件提示识别语义闭合。不再为了达到旧的 900 字符阈值拼接无关话题。

小事件 `memory_stage=0`，只保存正文和运行所需的编号、主体、对象映射、来源及时间。不调用事件丰富模型，不生成摘要、情绪、角色快照或白描。元数据中的对象映射用于作用域过滤，不是模型生成的角色分析。正文里已有的“姓名：句子”原样保留，程序不根据对象编号补写说话人。

写入只使用三个字数：`small_event_min_chars` 100、`small_event_target_chars` 300、`small_event_max_chars` 500。模型交回的一组落在 100 到 500 字之间就整组保存。不足 100 字留在残余，等待后续输入。超过 500 字时，每轮只切一刀，前段要落在 100 到 500 字之间；后段回到残余。这条路径按前段字数校验，不使用旧的 70% 到 90% 比例。切不开就整段保存。单句超过 500 字时，仍按字符分段。

闲置规则在新路径上也只看这三个数。不足 100 字的残余闲置满 7 天才封存。超过 500 字、切不开、闲置满 3 天的残余整段封存。没有新输入时，切剩的后段会一直留在残余里，直到这两条闲置规则或物理红线。

每个第一层事件按封存先后得到 `memory_sequence`。计数表在旧库上自动建立，首次用该主体已有的最大序号初始化。再次保存同一条事件时，按事件编号读取库里的旧号。上层事件记录 `memory_sequence_start/end`，表示它覆盖的编号范围。排序仍以经历时间为准，序号只作稳定标识。

近期小事件无摘要，向量及词面检索使用正文，取回时也读取放得进预算的完整正文。放不下不会截断。

## 同一个机制的多个阶段

默认魔法参数集中在 `src/rems/config.py` 的 `MemoryRefinementConfig` 和 `RefinementStage`：

| 参数 | 默认值与含义 |
|---|---|
| 阶段年龄 | 90、365 天，分别作为三个月、一年的工程近似；此后不再提炼 |
| 每阶段 L1 保留比例 | 1/3，按本轮 L0 字符数计算预算，不是语义保留率 |
| 候选窗口 | 约 5000 字符的连续、到龄事件 |
| 单批选择 | 从候选窗口后往前选择约 2000 字符；也可设为从前往后 |
| 每阶段每轮批数 | 1，避免一个积压阶段阻塞其他阶段 |
| 后台轮询间隔 | 3600 秒 |
| 轻量事件长度 | 下限 100 字，目标 300 字，检查线 500 字 |

这些值均可配置，不代表人类记忆的固定时间或压缩规律。阶段年龄必须严格递增，比例在 `(0, 1]` 内，选择预算不能超过候选预算。

候选先按原经历时间排列，取最早尚未处理的到龄窗口；从后往前选择时，选完仍按原顺序输入模型。预算包括事件间分隔符，完整事件不从字符中间截断；若一条事件本身超过窗口或批次预算，整条处理，所以两个字数是软预算。每轮重复运行会继续处理未吸收部分。

年龄以当前时间减原经历时间判断。跨日期事件按最新来源日期判断是否整批到龄；`event_time_start/end` 保留最早/最晚原始日期，`refined_at` 单独记录提炼时刻，后续阶段不会因为今天提炼而重新计龄。带时区的时间统一比较；无时区旧时间按 UTC 解释，以避免依赖宿主机器时区。

第一次提炼读取阶段 0 的正文。第二次严格读取上一阶段的 L1；缺少 L1 报错并保持原事件可见，不静默改用 L0。不会按相似主题随机聚类，也不会为了到龄强行生成未经证实的长期规律。默认只有这两个阶段。

## 提炼输出与完整性

新写入的原始断句按主体、稳定来源、原文位置与内容生成片段标识；过长断句的分片也保留稳定标识。接收批次时同时检查未闭合缓冲和已封存事件，避免上游只确认部分批次后重投剩余经历，造成原文重复进入不同事件。不同来源的相同表述、同一来源中不同位置的重复句子仍然保留。标识保存在已有 JSON 元数据内；没有稳定来源的旧输入不按文本猜测去重，旧库也不会自动清除历史重复。

先复用编号式边界解析，让模型只返回连续、完整事件的分组。每组 L0 由程序以双换行原样拼接选中的正文或 L1，不让模型重写它。模型可以生成多个组，不能归入已形成组的条目继续保留。每组再调用现有事件丰富流程，生成 L1 等摘要、主体情绪、对象事实及其分级表示。

每组独立保留 `source_events`、输入层级、原事件时间范围和正文字符区间。来源信息作为额外上下文提供给丰富模型，帮助识别不同来源的“昨天”等相对日期；这些说明不混入 L0 正文。它仍是模型解释日期，不是确定性日期解析器。

L1 写明每条直接子事件的代表句，格式是 `〔#序号〕` 后接一句，每句最多 60 字。序号来自子事件的 `memory_sequence`；没有单号时用起止编号。程序检查每个子事件序号是否都出现在 L1 里。对象映射里的名字、数字和日期只用来从该子事件中挑选句子，没有这些线索时仍保留该子事件的一句。来源记录里另存同一句，只供审计；下一阶段和默认回忆以 L1 为准。代表句放不进三分之一预算时，原摘要和代表句都保留，并在 `refinement_policy.representative_overflow` 记下超出。

提炼先在内存构造全部新事件，再准备其向量。SQL 发布前新 ID 不属于活动候选，无法被普通回忆选中。随后在一个数据库事务中保存新事件、对象事实，以及旧事件的隐藏关联。任意一步失败，原事件不隐藏；事务失败后清理尚未发布的新向量。比较并交换旧记录的可见状态，防止多个工作者重复吸收同一事件。

数据库是可见性的依据。发布后会移除旧事件向量；若清理失败，旧事件仍被候选过滤，后续 `backfill_index` 可重试清理。小库语义搜索也限定活动事件 ID，避免残留旧向量挤占候选。

普通检索不返回 `refinement_hidden_by` 非空的事件。原文、摘要、来源链和上层 ID 仍可直接审计读取。

上层事件被选入结果后，沿 `source_events` 找到第一层原文。每条原文另有一个材料类型为 `event_detail` 的向量，挂在可见的上层事件上。上层事件的语义分取自己的向量和这些原文向量中的最高分；原文向量不单独成为候选。词面分对摘要和每一条原文分别计算，取最高分。

只有相似度达到门槛的第一层原文才附在同一条结果后面。门槛默认是 `recall_semantic_min`，可用 `recall_detail.min_similarity` 覆盖。回放记下每条原文的相似度，不论是否附上，因此换门槛时不必重跑。纯词面检索不临时计算向量，也不附原文。默认最多附 1 条，由 `recall_detail.max_count` 配置，不随回忆档位变化。放不进剩余预算的整条不附。预算截取若会切进附加原文，就去掉整段原文。被附上的原文不另占一条结果，也不增加遗忘强度。

日期锚点由 `recall_detail.date_anchor_locale` 决定，默认中文，英文评测改为 `en`。上层事件和附加原文使用同一种写法。

## 启动与兼容

Python 调用：`pipe.refine_memory(subject_id, now=optional_datetime)`，单次调用有明确批次上限。

后台入口为 `python -m rems.jobs.refine_memory --subject ID`，默认运行一轮；添加 `--watch` 后按配置间隔持续执行。`--now` 支持单轮历史时间验证，不能与持续模式并用。应使用已安装本项目的 Python 环境。程序遇到错误输出结构化结果并退出，不在后台无限重试付费请求。

后台任务入口已经提供，但不会擅自在用户设备上安装系统定时任务或启动常驻进程。调用方可在维护周期调用上述接口，或启动持续模式。

旧版本事件的 `memory_stage` 默认是 `None`，继续可检索，不自动当作新轻量事件再次压缩。旧数据库无需破坏性迁移；新字段保存在已有 JSON 元数据内。若需要旧库迁移，应另行明确规则。设置 `memory_refinement.enabled=false` 可继续原来的即时完整事件路径。

原 L1→后级摘要规则暂时保留；小事件只存正文，只有首次及后续提炼才生成多级内容。每阶段的提炼次数和事件内部 L1/L2 层级是两个不同概念。

## 验证与评测边界

新回归覆盖小事件即时闭合且无丰富调用、交错句子原样拆成两件事、100/300/500 三个字数、超过检查线只切一刀且后段回残余、切不开则整段保存、说话人前缀在切分后仍在、不足 100 字等待、3 天与 7 天闲置、序号沿用、代表句序号、原文向量参与查找但不单独成候选、日期锚点、预算不切断附加原文。

LoCoMo 写入结束时没有统一封存。末尾不足 100 字的残余只能在未封存缓冲里按词面找到。复测时要单独说明，不能把它记成召回能力变差。

LoCoMo 对照沿用前轮完整历史、30 题、固定答案条目和真实 JShi 核心。事件长度和提炼次数的改动必须重新写入空库，不能声称与前轮是同一封存事件库的单变量消融。该历史只跨数月；一年阶段由时间模拟回归验证，不能冒充真实多年交互或多年问答成绩。
