# JShi 如何触发记忆写入，以及本轮回放的差别

2026-10-16。只读检查相邻 `../JShi` 当前源码；没有修改该项目、连接日常数据库或发起模型请求。

## 实际入口链

`SubjectProcess` 先将外部输入写入经历台账；回应/动作或内部状态也作为经历段写入。
活动结束时，`ActivityClose` 返回 handoff 标记，进程调用 `memory_control.run_async`。
它先回收上批后台结果，再判断是否需要提交；不满足条件则跳过。

默认控制器由 SubjectProcess 构造，未覆盖阈值。`memory_flush_chars()` 默认 3000，
可受 JShi 进程参数快照影响；这里核实的是源码默认值，不宣称已检查某个运行实例的有效配置。

## 默认触发条件

任一条件满足即可，按表顺序判定；前提是存在未投递经历、上一批未在处理、失败重试未耗尽。

| 条件 | 实际含义 |
|---|---|
| 原始文本累计 >= 3000 字符 | 数量触发阈值，不是批次硬长度 |
| 未投递经历 >= 20 段 | “段”包括输入、主体回复或状态，不等于 20 轮完整对话 |
| 距上次成功投递 >= 600 秒 | 有 pending 时触发；不是判断每两条消息之间的间隔 |
| 最新待投递经历距现在 >= 1800 秒 | 闲置触发 |
| 本地时间在 00:00–06:00 | 夜间有 pending 时触发 |

时间条件由控制器被调用时检查，控制器本身没有开一个独立定时轮询器。
活动收尾提供了实际调用点；是否有空闲活动持续驱动，需结合具体应用运行方式判断。

## 批次内容

`build_batch` 从 MEMORY 消费游标之后读取全部待投递经历，不把它们裁成固定 3000 字符。
每段附说话人，并保留 objects、interlocutor、source_ids、occurred_at、segment_id、origin。
此前后台处理期间新增的经历也可能累积到下一批，导致批次超过 3000。

REMS3 适配器把批次传到本项目的 `REMSPipeline.ingest_batch`。
本项目再将有效段拼成一次代谢输入，进入已有残影 + 新输入的事件剥离。
因此有三层长度：JShi 待提交批次、REMS 未完成缓存、最终事件，不能混为一个上限。

JShi 本身传递了发生时间，已定位的批次合并丢失 occurred_at 发生在 REMS 的合并构造阶段。

## 本轮评测如何不同

评测回放用了真实 JShi 台账、MemoryControl 批次构造和记忆适配器，
但将独立控制器阈值改为 flush_max_chars=1、flush_max_segments=1，
由回放程序累计约 3000 个原始文本字符后调用同步 run_once；每个会话末尾也提交。
主体是观察者，不生成替代历史回复；结束时另外强制封存残留。

所以它验证的是固定历史通过真实接口进入记忆后端后的表现，
不是 JShi 默认的 20 段/时间/夜间/后台调度策略。
说话人前缀和分隔符使最终后端输入长度与回放累计值也不完全相同。

## 独立判断

1. 3000 作为默认提交阈值有源码依据，但“每批固定 3000”不符合真实程序。
2. 正常事件剥离与超长处理必须适应长短不一的批次，不能靠上游精确切批来掩盖缺陷。
3. 无模型就能复现的两条重复封存路径、摘要没有预算验收、解交织绕过超长检查，
   都不依赖回放采用何种提交时机，仍是需要修复的确定性问题。
4. 两轮结果不能用于证明真实 JShi 调度已经验收。后续应保留固定批次诊断基线，
   同时另做默认触发策略对照：记录触发原因、投递段范围、实际字符数、源日期、
   后台状态与后端接管结果，再分别测试记忆事件形成和核心回答。
5. 接管与封存应分开确认：后端持有残影也是接管，但不是封存。
   目前 JShi 根据 stored_marks 推游标，REMS errors 仅作为结果字段返回，
   JShi run_once/drain 没有据该字段判失败。这是额外交接风险，需用失败和部分接管场景验证；
   尚未据此将本轮所有重复归因于上游重投。

## 程序位置

- `../JShi/src/jshi/core/params.py`：MEMORY_FLUSH_CHARS 与参数快照读取。
- `../JShi/src/jshi/subject/process.py`：控制器默认装配、经历入账、活动收尾异步投递。
- `../JShi/src/jshi/memorycontrol/inprocess.py`：触发判定、build_batch、后台投递及游标处理。
- `../JShi/src/jshi/memory/rems3.py`：契约转换与后端调用。
- `src/rems/pipeline.py`：本项目批次合并、代谢调用、封存回执。
- `src/rems/eval/runtime.py`：本轮同步回放的约 3000 字符提交策略。
