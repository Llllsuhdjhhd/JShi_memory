核心关系一句话：这些不是"和回忆并列的东西"，而是回忆的"原材料和权重"——写入端把它们存下来，回忆端把它们变成"按查询排序的证据"。事件是回忆的单元，对象是过滤维度，情绪是调制器，遗忘因子是强度权重。逐一对号：

- 事件（Event）= 基本召回单元。一切检索粒度都是事件：向量索引点、RRF 打分对象、返回片段，全是 event_id。
- 原文 L0 + 摘要 L1~Ln = 检索文本 + 分层输出。retrieval_text 用 L1 做向量索引；_select_summary 按查询的 level 取 L1/L2/L3 返回。
- 对象（role_list / 白描）= "谁"维度：过滤 + 一路 RRF。查询指定对象时只搜该对象参与的事件；对象白描 l1/l2/l3 是事件的快照内容，不直接参与排序。
- 感情（emotion / valence / arousal）= 调制器。查询带情绪时，与事件 valence 匹配的 +25%、不匹配的 −10%。
- 遗忘因子（forgetting_factor）= 强度权重。有效分 = forgetting_factor × 0.5^(年龄/半衰期)，低于静默阈值的直接不召回；命中一次会写回强化 ×1.5。

两个容易混的点：感情和遗忘因子不是一层东西。感情是事件的内容属性（这件事对匠石意味着什么）；遗忘因子是记忆系统的元数据/物理强度（这条记忆当前有多容易提取）。连接点是写入时 arousal 映射成初始遗忘因子——情绪越强烈越难忘，这正是 role_service.py 里已有的 100 × arousal^γ 公式，但 memory 路径封存事件时只写了 activation_energy = arousal，没有用它初始化 forgetting_factor，所以现在所有事件都是 1.0。

对象和感情的关系是"分离"的。按 JShi 约束，白描是匠石对对象的客观描述（分级、无情感），情感只属于主体，所以 emotion 挂在事件上、不在对象上。对象在回忆里只有"索引/过滤"作用。

整个闭环用认知科学的说法：编码（ingest）= 原文 → 事件封存（摘要、对象白描、情绪）→ arousal 决定初始强度 → 索引；提取（recall）= 查询 → 多路召回 → 融合排序 × 强度 × 情感调制 → 按层级输出；再巩固（reinforce）= 命中一次遗忘因子 ×1.5。对照现实记忆：事件=情景记忆条目，对象=人物索引，情绪唤醒=记忆巩固强度，遗忘因子=可提取性，回忆=提取过程且提取会改变记忆本身。
