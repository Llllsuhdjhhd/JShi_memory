结论先说：推荐"开源检索组件 + 自己写编排"的组合路线——也就是你选项里的第 2 种为主，第 1 种只覆盖 JShi 特有的薄层，第 3 种（整包换 Mem0/Zep/Letta）不推荐。

判断依据不是偏好，而是三个客观标准：

1. 这一层是不是你的差异化/研究点。检索内核（向量检索、BM25、RRF 融合、重排）不是，它是 2020 年就已收敛的成熟商品。JShi 的差异化在别处：事件级分层摘要、对象白描时间线、遗忘/强化语义、活跃区与个人世界。这些才值得自己写。
2. 开源件的接口是窄还是侵入。Qdrant 的接口是"向量进、排序出"，不碰你的 schema——窄接口，接入成本极低。而 Mem0/Zep/Letta 的接口是"把你的记忆塞进它的实体/图谱/角色模型"——宽接口，会强制改写语义层。
3. 有没有测量闭环支撑新算法。目前没有。在没有 Recall@K 标注集之前，任何"自己发明新检索算法"的主张都缺乏证据；正确顺序是先上成熟件、建测量、再谈优化。

具体到代码现状（我核对了 recall/pipeline.py），RecallPipeline 骨架其实已经是对的：多路召回 → RRF → 遗忘/情感调制 → 可选重排 → 分层选择 → 强化。缺的不是架构，是四个"半成品"：嵌入是占位的（测试用 hash），需换 bge-m3 或 bge-base-zh 重建索引；对象路是断的（_object_route 还在读 object_timeline_repo，但白描迁移后不再写入，应改绑 role_list / Qdrant payload 的 object_ids）；遗忘因子恒为 1.0（arousal 未映射到记忆强度，应 seal_event 时按 memory_weight = f(arousal) 初始化）；无近因独立通道、无查询意图分类。

落地路径：1. 嵌入换 bge，Qdrant 开混合（dense + BM25 sparse + RRF）；2. 重排接 bge-reranker-v2-m3，只对 top 20 精排；3. 修四个缺口（对象路、遗忘初始化、近因、意图），都是百行级改动；4. 同时建 Recall@K 标注集，用真实对话查询、人工标注预期命中，跑消融，用数据定参数。

一句话：检索内核买现成的，记忆语义自己写，测量闭环必须建。
