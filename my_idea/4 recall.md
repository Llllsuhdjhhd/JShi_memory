## 4. 事件代谢素材、触发机制与回忆提取规范

### 4.1 残影（Shadow）与未完成事件的统一定义

- **残影**：系统中所有未完成事件内容的物理拼接。它不再作为独立的缓冲区存在，而是未完成库在原始文本层面的"视图（View）"。
- **未完成事件库**：存储已开启但未闭环的逻辑对象（`UnclosedEvent`）。关键字段：
  - `content_fragments`：按时间累加的片段列表，`merged_content` 为拼接后的原文；
  - `logical_gaps`：模型识别出的"仍缺什么"的自然语言描述；
  - `**split_prefix_event_ids`**：若本条是某次 80/20 强制分裂的"尾段"，记录它前面的前缀事件链（自远而近）。UC 最终闭环为事件时该链会被完整继承到新事件的 `split_prefix_event_ids`，并同时反向写入每个前缀事件的 `split_successor_event_ids`（见 §1.1.9）。
  - `**oversized**`：审计标记。当评估器判定该 UC 累计已越过 `len_msg × unclosed_force_ratio` 红线、且认知层修复 skill 也放弃切分时，该条 UC 以 `oversized=True` 原样保留在库中——**不**走 `seal_event`；仅在物理红线（`physical_redline`）被真正触发时，由 §4.2 最后一层兜底 force-seal（此时封存事件仍会继承已有前缀链）。
- **动态关系**：
  - 输入摄入时，系统提取所有未完成事件并拼接为残影。
  - 回忆检索与边界检测均以"残影 + 最新输入"作为全文上下文。
  - 边界检测剥离出"已闭环事实"（封存为基本事件，包括 80/20 分裂的**前缀事件**）与"新/后续未完成片段"（包括分裂的**尾段 UC**，携带前缀链）。
  - 代谢完成后，残影根据更新后的未完成库重新生成。
- **复杂输入的精准剥离案例**：
  - 当系统接收到输入："我去跑了步，然后就回家了。回家后我打扫了卫生，然后继续进行A项目的研发，大概1小时后，看了一会儿小说"。
  - 判定与剥离逻辑：大模型扫描到"A项目的研发"时，通过检索命中未完成事件库中的历史挂起事件（例如几天前开启的 A 项目逻辑实体）。此时，系统必须精准划开边界：将"打扫卫生"与"看小说"剥离出来作为全新的基本事件封装；将"继续研发A项目 1小时"单独抽离，归入库中已存在的 A 项目未完成事件，更新其完成进度与状态。这种分离机制保证了宏观长期任务与微观即时琐事的物理隔离。

### 4.2 事件剥离与序号编码协议、语义闭包与碎屑代谢

为了最大限度优化模型在代谢过程中的 Token 消耗并维持回忆上下文的纯净度，系统全面采用 Sentence-ID Encoding（序号编码）协议，并引入严密的"语义闭包"与"碎屑代谢"机制。

#### 4.2.1 语言学视角的边界界定与"语义闭包 (Semantic Closure)"

- **分句索引化**：系统将一段充满冗余、交叉的残影（Shadow）文本预先进行语义分句，并标记为 `[序号]` 文本格式。同时在 prompt 中显式标注"既有残影序号区间"与"本轮新输入序号区间"，防止模型把两者混为一段。
- **零文本返回与语义闭包约束**：在剥离事件（Disentanglement）时，大模型通过返回对应的句序列表 `content_raw_indices`（例如 `[1, 2, 5]`）来界定范围，禁止返回原文 text。
  - **闭包校验规则**：大模型在挑选序号时，必须保证所选序号构成一个**"语义闭包"**。即：如果句 5 存在对句 4 的强依赖指代（如代词"他"、"然后"等衔接成分），则句 4 和句 5 绝对不可被割裂。剥离出的事件必须在孤立状态下具备完整的主语、谓语及语境连贯性。
  - **续写判定**：若当前片段是未完成事件库中某条的续写，在对应 completed 片段上填写 `continuation_of = "UC-xxx"`；闭环后该 UC 被删除，其内容与当前片段合并为新基本事件。
- **物理还原逻辑**：系统在接收到模型返回的索引序列后，在本地（EventService）直接根据索引碎片还原出完整的 `content_raw`，消除了模型搬运原文产生的幻觉（漏删、错字）。

#### 4.2.2 心理学与 AI 视角的"饼干碎屑 (Cookie Crumbs)"处理机制

在执行完主事件剥离后，未被选中的剩余序号文本（如上例中的句 3、句 4）若无法独立成事，即沦为残缺的"碎屑"。若任由碎屑在残影库累积，将导致大语言模型的上下文注意力崩溃（Attention Pollution），并严重污染后续的实体回忆块。为此引入以下三段式代谢：

- **机制 1：向上吸收 (Semantic Absorption)**
  - 在**剥离事件（BoundaryDetection）的过程中，大模型在挑选主干序号时，若检测到相邻的"碎屑"仅仅是对主事件的微小心理反应或环境描写（如"当时风很大"、"我感到一阵疲惫"），这些碎屑禁止**被遗弃在残影缓冲区。它们必须被直接**"向上吸收"（合并选中）**，作为附属序号一并返回，以便将其合并打包到完整的 `content_raw` 中，从而彻底清空缓冲区的冗余碎片。
- **机制 2：影子降噪压实 (Shadow Compaction)**
  - 为了防止 AI 在下一次解析时面对支离破碎的半截病句，当残影缓冲区内的碎片数量达到一定阈值（或呈现明显的语法断层）时，触发"压实"指令。调用 LLM 将当前的残影碎片重新用平滑的自然语言改写为连贯的背景状态描述，消除语法孤儿，确保输入给下一轮代谢的上下文始终纯净。
- **机制 3：无主碎屑的垃圾回收 (Garbage Collection / Trace Decay)**
  - 模拟人类大脑工作记忆的痕迹衰退（Trace Decay）。为残影库中的独立碎屑分配生命周期（TTL）。如果某段碎屑在连续 $N$ 轮交互或经过一定时间跨度后，仍未能与新输入拼接成闭环事件，系统将判定其为毫无价值的背景噪音，并将其物理抹除。坚决避免无主碎片长期挂起并拉偏后续人物召回的向量检索方向。

#### 4.2.3 剥离与代谢的工程管线整合

架构层面允许「剥离 + 摘要 + 角色」在一次 LLM 调用中完成。本参考实现出于 prompt 噪声控制与角色抽取稳定性考虑，将其拆分为两步：

- BoundaryDetectionSkill：执行序号剥离、校验语义闭包、执行"碎屑向上吸收"（将环境/心理等微小描述合并入选中的序号中）、判断残影与未完成事件、**执行 80/20 强制分裂（§4.2.4）**；
- EventEnrichmentSkill：基于包含已吸收碎屑的完整 `content_raw`，按以下三种工作模式之一产出摘要 / 角色，同时将环境/心理描写结构化写入 `decoration` 字段。
- **超长未完成的三段式兜底（取代原有盲目 force-seal）**：当单条未闭环片段累计越过 `msg_len × unclosed_force_ratio` 红线时，系统**禁止**直接调用 `seal_event`。顺序为：(1) 认知层 80/20 分裂（§4.2.4）→ (2) 评估器 + 专用修复 skill（§4.2.5）→ (3) 物理红线 force-seal（仅作为缓冲区防溢出）。在第 (1)(2) 层失败但尚未击穿物理红线时，UC 以 `oversized=True` 审计标记原样保留在库中。

##### 4.2.3.1 EventEnrichmentSkill 三种工作模式（2026.05 修订）

`EventEnrichmentSkill.enrich(...)` 根据上游传入的角色信息形态在三种模式中路由（优先级 `skip_roles` > `names_only` > `full`）：


| 模式                      | 触发条件                                                                        | LLM 输出                                                                         | snapshot / 8 维情绪来源                                                                       |
| ----------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `full`                  | `pre_role_entries` 为空（pre-recall 未抽到角色）且未 `skip_roles`                      | 摘要 + **完整角色**（含 snapshot + 8 维情绪）                                              | LLM 同次产出                                                                                 |
| `**names_only`（默认对话流）** | pipeline pre-recall 已经抽到角色，把 `role_entries`（含 snapshot + 8 维情绪）作为「全局富信息池」下放 | 摘要 + **本事件实际登场的角色名字符串数组**（如 `["贾雨村", "娇杏"]`）；不出 `role_id` / snapshot / emotion | 后端用名字对 `known_roles`（含 aliases）做**字符串匹配**解析 `role_id`，再从 pre-recall 池回填 snapshot + 8 维情绪 |
| `summary_only`          | 外部已经显式构造了完整 `role_entries` 或显式 `skip_roles=True`                            | 仅摘要                                                                            | 由调用方提供                                                                                   |


`names_only` 路径的设计动机：pipeline pre-recall 阶段已经在 `shadow + raw_input` 完整上下文上调用 `RoleExtractionSkill` 抽出过一份"全局角色池"，每个角色的 snapshot 与 8 维情绪都基于完整上下文判定；事件级 enrichment 只需要回答"这条 sealed event 里**实际登场**了池中哪些角色"——一个轻量的"摘要 + 角色名字符串数组"调用就够了，避免为每条事件让 LLM 把 snapshot/情感重做一遍。

`names_only` 的 LLM 契约（与 `full` 路径一同输出 role_id + 各级 snapshot + 8 维 emotion 的对比）有意只让模型出名字数组，`**role_id` 完全由代码用字符串匹配解析**：把 `known_roles.name` 与 `known_roles.aliases` 全量摊平成 `name → role_id` 字典，命中即取池中富信息条目；prompt 端要求 LLM 命中已知角色时**输出该角色在已知列表里的规范名**（"雨村" → "贾雨村"），降低匹配失败概率。

事件最终 `role_list` 仍只包含本事件真实出场的角色子集，富信息从池里直接复制；池外新角色（极少数 pre-recall 漏抽场景）走兜底路径自动注册并以空快照入库（带 `info` 日志）。

数据下放路径：`REMSPipeline.ingest` → `MetabolismService.process_input(pre_role_entries=role_entries)` → `_apply_boundary_result` / `_force_save_all` → `EventService.seal_event(pre_role_entries=...)`，最终在 `seal_event` 里完成模式选择与池回填。

#### 4.2.4 超长未完成事件的 80/20 强制分裂（Forced Split at Logical Closure）

针对未闭环叙事"越聊越长但始终不结案"的长上下文病态（典型：长篇小说叙事、会议实录），系统要求边界检测模型在识别到某条未完成叙事累计越过 `force_threshold = msg_len × unclosed_force_ratio`（默认 1.2）时，**必须**在**最近的逻辑相对闭环处**（动作回合收束 / 场景过渡 / 对话告段落 / 情绪收束）把它切成两段，而不是机械按字数硬切。

- **分裂比例**：前段长度目标约 **80%**（可接受区间 70%–90%，由 `boundary_split_ratio_`* 配置）；
- **前段语义**：构成一个相对独立的逻辑闭环，可独立理解、可独立封存为一条基本事件；
- **后段语义**：继续作为新的未完成叙事挂起；
- **配对声明**：前后两段在同一次模型返回中通过一个自造的 `split_id`（形如 `"SP-1"`/`"SP-2"`，同一响应内唯一）显式配对；系统借此把前缀事件 ID 回填到后段 UC 的 `split_prefix_event_ids`（见 §1.1.9）。

**边界检测 JSON 输出字段表（2026.05 修订）**：

```json
{
  "completed_events": [
    {
      "content_raw_indices": [1, 2, 5],
      "continuation_of": "UC-xxx 或 null",
      "is_split_prefix": false,
      "split_id": null
    }
  ],
  "new_unclosed": [
    { "indices": [12, 13], "split_id": null }
  ]
}
```


| 字段                    | 归属                       | 含义                       |
| --------------------- | ------------------------ | ------------------------ |
| `content_raw_indices` | completed                | 事件命中的句子序号列表（零文本返回）       |
| `continuation_of`     | completed                | 续写目标 `UC-xxx`，闭环后该 UC 被删 |
| `is_split_prefix`     | completed                | 是否是某次强制分裂的 80% 前缀        |
| `split_id`            | completed / new_unclosed | 分裂配对 ID；两侧必须成对出现         |
| `indices`             | new_unclosed             | 该未完成事件命中的句子序号列表          |
| `logical_gaps`        | new_unclosed（可选）         | 模型识别的"仍缺什么"              |


兼容性：旧格式 `new_unclosed_indices: [12, 13]`（扁平）或 `[[12,13],[20,21]]`（嵌套）仍被解析，但该路径**无法**声明 `split_id`，故不会触发分裂配对；需要配对时必须使用新的 `new_unclosed` 对象写法。

#### 4.2.5 通用 Skill 评估 / 修复协议（Evaluation & Remediation）

对每个 LLM 技能的输出，系统都可以挂接**评估器（SkillEvaluator）与修复器（SkillRemediator）**，形成"调用 → 评估 → 必要时修复"三段式。协议硬性约束：

1. **评估只做一层**。修复器返回的新输出**不再**进入评估，防止"评估-修复-评估-修复"的无限递归。
2. 一次 skill 调用可挂多个评估器，按**严格合并**（任一失败 → 整体失败）聚合报告；修复器只有一个。
3. 评估器可以是**规则型**（零 LLM 成本、始终开启）或**LLM 型**（使用另一模型对本次输出进行打分评价；默认关闭，成本敏感）。
4. 修复器可以是"同 skill 再跑一次带额外参数"，也可以是一个**独立的窄范围 skill**（只做一件事，便于快速收敛）。
5. 评估失败且修复失败时，调用方按"降级保留"策略处理——**不**把责任推给下游 `seal_event` 等高代价组件。

对应到 BoundaryDetection 的配置：

- **评估器**：`BoundaryForceThresholdEvaluator`（规则型，默认启用）。检查
  - `oversized_uc`：任一 `new_unclosed` 越过 `force_threshold` 且未声明 `split_id`；
  - `split_tail_still_oversized`：已配对但尾段本身仍越阈值；
  - `broken_split_pair`：两侧 `split_id` 不一一配对（孤儿前缀 / 孤儿尾段）；
  - `split_ratio_off`：分裂比例显著偏离区间，仅 warn 级别，不阻塞。
- **修复器**：`OverlongUCSplitRemediator`（默认启用，`boundary_remediation_enabled`）。对每一条越限 UC 独立调用一次 `OverlongUCSplitSkill`（只做"逻辑闭环二切"这一件事，prompt 直接给原文不走句子编码），把原条替换为"`completed_events` 新增一条带 `split_id` 的前缀 + `new_unclosed` 替换为带同一 `split_id` 的尾段"。修复器会做原文字符等价校验（防止 LLM 改写）与比例硬防线（超出 ±5% 立即放弃）。
- **全部失败的兜底**：越限 UC 原样保留 + `oversized=True`；等 §1.1.7 第三道物理红线触发时再强制回收。

协议是 skill-agnostic 的——`EventEnrichmentSkill`、`InductiveEvolutionSkill` 等可复用同一套接口挂接自己的评估器（如"角色列表为空但原文出现角色"、"抽象 `content_raw` 超目标 2×"等）。

### 4.3 动态信念修正与知识冲突处理

在长期记忆中，"知识冲突"不可避免，系统将其区分为两种底层逻辑进行处理：

- **事实的自然演进**：有些冲突本身就是事物随时间发展的客观事实（如从喜欢苹果变成对苹果过敏）。此类信息不视为逻辑错误，系统依靠白描时间戳作为最新状态追加，依靠遗忘机制使旧状态自然衰退。
- **技术性与代差修正**：有些冲突是技术原因导致的（例如此时的模型推导结论不如将来的模型版本先进）。针对此类认知冲突，仲裁机制应赋予"未来时间点/更先进模型的判断"以绝对的采信权重，直接对旧有认知执行逻辑覆写（Tombstone 墓碑化）。

### 4.4 记忆召回机制：耳蜗共振三频段向量模型（重构）

**【新增】**：以下为三频段解耦向量的完整定义与工程落地策略。

#### 4.4.0 三频段解耦向量定义与工程落地（2026.06 重构）

抛弃传统单维文本向量，模拟人脑耳蜗的频率空间分离与神经调谐曲线，实现多维度情绪与事实共振。原独立的白描时间线检索流（流 B）被废除，完全融入统一的频段共振体系。

**频段切分定义（1536维示例）**：

- **动作/事实频段**（$\vec{V}_{act}$，0-511维）：入库侧在 `act_embed_max_chars` 内取最长可用摘要（L1–Ln 级联）；查询侧对 **search_text（残影+当前块）** 经 LLM 压缩一次，C/S/E 多路检索共用同一份 act 摘要。默认经 **IngestLlmSession** 三 turn：Turn1 压缩（阻塞 recall）→ Turn2 角色（与 recall 并发，不重复贴全文）→ Turn3 边界（分句编号表）；API 无跨请求记忆，靠同一 `messages` 历史续问。
- **情绪/效价频段**（$\vec{V}_{emo}$，512-1023维）：将基于 8 维情感模型计算得出的 $(\bar{v}, \bar{a}, E)$ 等标量，通过密集层非线性投影升维获得，承载情感共振信息。默认配置下 **不参与 Qdrant 向量检索**（$\beta=0$），仅经 Mood Modifier 在 RRF 后重排。
- **人物/实体频段**（$\vec{V}_{ent}$，1024-1535维）：基于事件独立 role_list（标准化 ID 与别名）生成，承载角色关联信息，在数学上等价于原独立白描流。

**现代工程落地策略：原生多向量与兼容降维双轨制**：

在实际工程落地中，针对不同的中间件基础设施，采用"原生为主、降维为辅"的双轨制策略：

- **方案 A：原生多向量字段（推荐）**
现代主流向量数据库（如 Milvus 2.4+、Qdrant 1.7+ 等）已原生支持在单一数据实体下挂载多个独立向量字段。
  - **入库侧**：将 $\vec{V}*{act}, \vec{V}*{emo}, \vec{V}_{ent}$ 保持原生维度，作为三个独立的 Vector Field 存入同一数据条目。
  - **查询侧**：通过数据库的原生 API 发起混合向量查询（Hybrid/Multi-Vector Search），直接在查询条件中下发权重 `{"vector_act": α, "vector_emo": β, "vector_ent": γ}`。
  - **架构优势**：各频段物理隔离，支持独立更新（如仅修正事件情感不影响动作向量）；底层 ANN 检索引擎并行扫描效率高，避免长向量造成的 HNSW 索引臃肿。
- **方案 B：拼接内积法（兼容老旧中间件）**
为了兼容仅支持单一向量的传统中间件（如 FAISS 早期版本）：
  - **入库侧**：将三组独立子向量分别作 L2 归一化，物理拼接后作为单向量入库：$V_{total} = [V_{act} || V_{emo} || V_{ent}]$。
  - **查询侧**：动态分配调谐权重 $\alpha, \beta, \gamma$（和为1）。将其直接标量乘到各自生成的查询子向量上并拼接：$Q_{total} = [\alpha Q_{act} || \beta Q_{emo} || \gamma Q_{ent}]$。
  - **距离引擎**：配置向量库使用**内积（Inner Product, IP）**。由分配律可知，底层会自动完成带权重的三频段共振打分。

**废除白描流（流 B）与意图路由（2026.05 修订：软混合权重）**：

原独立的**白描时间线检索流（Stream B）被废除**，完全融入统一的频段共振体系。上游通过**前置轻量意图分类器**（`RecallIntentClassifier`，零额外 LLM，位于检索关键路径）确定检索倾向。下列三组权重**不再是硬三选一**，而是作为**锚点权重**，由分类器输出的混合系数做**凸组合**后得到实际下发的 $(\alpha, \beta, \gamma)$：

- **事实追问（fact 锚点）**：$\alpha=0.7, \ \beta=0.1, \ \gamma=0.2$（以客观事件为主）。
- **情绪共振（emotion 锚点）**：$\alpha=0.2, \ \beta=0.6, \ \gamma=0.2$（以情感共鸣为主）。
- **白描寻踪（entity 锚点，人物轨迹）**：$\alpha=0.1, \ \beta=0.0, \ \gamma=0.9$。此时 RAG 在数学上自发退化为"纯人物轨迹行为搜索"，等效于原流 B 的功能。

**软混合机制（去正则硬选）**：分类器对查询计算三类信号强度——(1) 可配置词典（entity / emotion / fact 三张词表，子串命中计数；fact 另含基线分 `recall_intent_fact_baseline`，保证无任何信号时回退到事实锚点）；(2) 可选的原型向量余弦（`recall_intent_prototype_enabled`，默认关闭，用现有嵌入器对各类种子短语预编码取相似度）。三类信号经 softmax（温度 `recall_intent_softmax_temperature`）归一为混合系数 $(\alpha_{ent}, \alpha_{emo}, \alpha_{fact})$，最终权重为三个锚点三元组的凸组合。如此"他当时害怕谁"这类混合意图能同时激活实体与情绪频段，而非被硬归一到单一类别。可置 `recall_intent_soft_blend_enabled=False` 回退到旧的正则硬选 dominant（便于 A/B 对照）。

#### 4.4.0.1 查询构造：人物提取并发 + 多路召回并集（2026.05 修订）

**人物提取并发化**：回忆所需的"焦点角色"信号与代谢所需的"全局角色池"由 `RoleExtractionSkill` 在 `残影 + 当前输入` 上一次性抽取。该抽取是纯 LLM 调用，**在后台线程并发执行**；回忆默认**不等待**其结果（`recall_wait_for_role_extraction=False`），而是用零 LLM 的即时启发式焦点（对已登记角色名/别名做字符串匹配）先行检索，保证回忆链路的低延迟。抽取结果在进入代谢封存之前于主线程取回并完成 `resolve_and_register`（角色入库写操作保持单线程串行），照旧作为 names_only 富信息池下放（见 §4.2.3.1）。置 `recall_wait_for_role_extraction=True` 时回忆改为等待完整抽取结果，焦点角色与查询效价更精确，但延迟更高。

**多路召回并集**：查询向量不再是"残影 + 当前输入"单路编码，而是构造多条互补查询路，各自独立检索后按 event_id 取最小距离**并集**（下游打分 / RRF / 压缩逻辑不变，并集只增加候选、不改变排序口径）：

- **路 C（当前句）**：仅编码当前输入，保证当前话题主信号不被长残影稀释；
- **路 S（上下文）**：残影（按 `recall_query_shadow_cap` 取尾部，默认 1200 字；≤0 表示不截断）+ 当前输入，保叙事连续；残影为空时本路跳过；
- **路 E（实体锚定）**：以焦点角色名/别名拼成 `entity_hint` 偏置实体频段，保底拉取角色相关事件；无焦点角色时本路跳过。

单路候选条数由 `recall_n_results`（默认 60）配置；可置 `recall_multi_route_enabled=False` 回退到单路"残影 + 当前输入"。命中过弱时仍按 §4.7.1 触发 Bypass 全量扫描，其结果与多路并集合并。

#### 4.4.1 双流记忆召回机制（Dual-Stream Recall）与代谢演化

回忆块（Recall Block）是 REMS 的核心感知源。系统摒弃了单一且脆弱的硬交集逻辑，采用包含 RRF 融合与无量纲平滑修饰的动态重排架构，以确保"语义相关"、"角色连贯"、"记忆巩固度"以及"情绪一致性"的物理与数学平衡。

- **阶段 1：统一频段共振检索（2026.06 修订）**：
  - **流 A (基本事件流)**：不再进行全量向量空间的无脑盲搜，而是利用由离线异步批处理（详见 §4.5）基于加权随机算法（A-Res）预抽取的"活跃记忆子集"（物理上限如 10 万条）作为前置硬过滤边界。同时，受 §4.6 的 PerfMonitor 动态控制，实际下发给向量数据库的候选 ID 数量会根据当前系统负载动态收缩（如负载高时仅截取活跃池的前 2 万条）。直接在限定的 `active_event_ids` 中进行**三频段共振向量检索**，获取 Top-60 语义相关事件。系统在此模拟人类"发生过什么事"且"尚未完全遗忘"的情景记忆读取。
  - **流 B (白描流)**：【已废除】原独立白描检索流的功能由人物/实体频段（$\vec{V}_{ent}$）权重 $\gamma$ 完全替代。当意图分类器判定为"白描寻踪"时，设置 $\gamma=0.9$ 即可在数学上退化为纯人物轨迹搜索，等效于原流 B。命中后，系统根据动态 `effective_forgetting`（已包含物理时序衰减）因子对相似度进行实时削减。已静默（有效权重低于阈值）的条目在此阶段被绝对过滤。
- **阶段 2：无量纲动态融合重排算法 (Dimensionless RRF & Bounded Modifiers)**：
为彻底解决绝对分跨度过大带来的"乘法失真（量纲灾难）"，系统抛弃原始余弦相似度绝对值，以名次（Rank）计算基准分，并采用平滑有界对数函数（Squashing Function）进行乘数约束。最终截取 Top 60：
`Final Score = RRF_Score * Factor_Modifier * Mood_Modifier`
  1. **基准分：倒数秩融合 (RRF Score)**：
  $RRF\_Score = \frac{1}{k + Rank_A} + \frac{1}{k + Rank_B}$（常数 $k$ 默认取 60）。
  若事件仅出现在单一流中，未出现的流 Rank 视为无穷大（得分为 0）。RRF 将所有底层的向量得分严格归一化到了一个极其微小且平滑的安全区间（约 $[0, 0.033]$），作为修饰倍数的基座。
  【注】：若采用原生多向量方案A，$Rank_A$ 为三频段混合搜索的综合排名；若采用拼接内积方案B，$Rank_A$ 为拼接向量的内积排名。流B已废除时，$Rank_B$ 视为无穷大，RRF 退化为仅依赖流A的单流分数，但此时三频段权重已承载了原双流的全部区分能力。
  1. **遗忘因子增益平滑修饰 (Factor Modifier)**：
  底层的 `effective_forgetting` 既承载了绝对时序的指数衰减，又承载了 LTP 记忆巩固。为了不让极端巩固的记忆（如权重高达 150）在乘法中失真，引入对数约束算法将其转化为一个有界乘数：
  $Factor\_Modifier = 1.0 + \alpha \cdot \log_{10}(1 + effective\_forgetting)$（其中 $\alpha$ 为控制增益幅度的超参，如 0.5）。
  这使得高度巩固的记忆能获得 1.x 倍到 2.x 倍的温和奖励，而不是粗暴地放大百倍，确保"语义与角色名次"永远是检索排位的核心基石。
  1. **情感共振修饰 (Mood Modifier)**：
  提取该候选记忆的原始效价 $(v)$，与实体当前的滚动情绪效价 $(\bar{v})$ 进行极性校验。若效价同号（例如处于愤怒状态时检索到了令人愤怒的历史事件）：
  $Mood\_Modifier = 1.0 + \beta \cdot (v \times \bar{v})$（$\beta$ 默认 0.2）。
  否则 $Mood\_Modifier = 1.0$。这使得底层检索动态拟合生物大脑"心境状态依赖"的提取倾斜。
  【注】：情绪共振修饰与 §4.4.0 的情绪频段（$\vec{V}_{emo}$）权重 $\beta$ 形成双层情感驱动——前者在向量相似度层面共振，后者在重排序层面做极性校验，两者协同但互不冗余。
- **阶段 3：记忆加强与情绪脱敏 (Consolidation & Habituation)**：
成功进入回忆块并输出给下游的事件，将触发双重代谢反馈：
  1. **语义事实固化 (LTP)**：该条目的 `forgetting_factor` 获得显著恢复，甚至突破基础值（长时程增强，见 §2.3），强化其结构性长期记忆的地位。
  2. **情绪脱敏 (Habituation/Extinction)**：该记忆条目绑定的初始情感强度参数 $(v, a)$ 将触发微量衰减折扣（如每次提取下降 1%）。这一机制完美模拟了心理学中"时间冲淡了情绪刺激，但反复提取固化了客观事实"的神经习惯化过程。
- **索引层粒度对齐（默认档）**：
  - 无论是基本事件还是抽象事件，写入向量库与回忆展示均默认采用 summaries 的中位档摘要，避免语义漂移。
- **动态预算分配与降级**：
  - 最终回忆块按 §1.2 动态压缩率执行"懒索引"降级（L1 -> mid -> max summary level），确保在 1/6.6 物理红线内最大化信息熵。

#### 4.4.2 80/20 分裂前缀的硬性展开（Split-Prefix Expansion）

当某条被召回事件 E 的 `split_prefix_event_ids` 非空时，说明 E 是一段超长叙事的"尾段闭环事件"，它前面的所有前缀事件构成不可切断的叙事链（见 §1.1.9）。在 `_assemble_block` 完成后、返回调用方之前，系统执行一道**硬性展开**：

1. **必现**：E 的 `split_prefix_event_ids` 中的每一条前缀事件，**必须**出现在最终回忆块中——无论它们自己是否直接命中语义/白描检索。
2. **时间语序**：前缀事件按"自远而近"顺序排在 E 之前；若某条前缀本身也有前缀链（多跳），其祖先前缀先于它出现。即便某条前缀恰好已被 RRF 排在 E 之后进入 block，系统也会把它**重排**到 E 之前，保留叙事可读性。
3. **允许降档，禁止丢弃**：新追加的前缀事件初始以"比默认档再压一级"的摘要落块；若累加后越过 `physical_redline`，系统只会把**前缀事件**降级到 ultra-concise（`[EVT-xxx] <stub>…`）形态，**锚定事件**（E 本身及其它正常命中事件）保持原档。任何情况下前缀事件都带 `event_id`，可追溯。
4. **链深度上限**：沿 `split_prefix_event_ids` 向上展开的最大跳数由 `recall_split_prefix_max_depth`（默认 3）控制。超深度的早期前缀按"已被抽象合成承载"的语义交由 §3.2 频繁子集挖掘去覆盖，不再逐跳回拉。
5. **去重**：同一前缀事件在多条命中事件间共享时，只入一次。

语义目标：用户的原始长叙事即便被 80/20 切成多段，也能在单次回忆中被完整再现——不会出现"只看到收尾、前面的铺垫全丢"的认知断层。

### 4.5 读写分离的双层存储架构与概率预取机制（千万级吞吐核心）

针对海量历史事件（突破千万级时）在向量检索中直接计算"加权随机概率"所引发的 I/O 与 CPU 性能雪崩，系统彻底抛弃了在线过滤的幻想。通过在架构层引入"A-Res 算法降维"与"双层异构存储"，将复杂的概率运算物理隔绝在 RAG 检索链路之外。

#### 4.5.1 第一步：基于 A-Res 算法的概率降维（前置计算）

为了保证 RAG 检索的极低延迟，概率运算被前置到数据写入以及离线更新阶段。基于 Efraimidis-Spirakis（加权随机抽样）算法的数学定理：

- 提取事件当前的动态遗忘因子 $w_i$：**基本事件**取自身 `role_list` 中 importance 最高（S > A > B > C > D）角色对应白描条目的 `effective_forgetting`（已含时序衰减与 LTP 巩固，见 §2.3），同级并列时取 max；**抽象事件**（`role_list` 恒为空）先将 `source_events` BFS 展开至叶子基本事件，再在该叶子集合上按同样规则取 $w_i$。事件不单独持久化 $w_i$，离线批处理自白描表派生重算。

**【新增】双因子复合有效权重**：系统不再仅使用单一遗忘因子，而是同时纳入抽象遮蔽因子，计算综合存活权重：
$$w_{effi}(t) = w_i(t) \times (1 - ASF_i)$$
其中 $ASF_i$ 为事件累积的抽象遮蔽因子（见 §3.4），范围 $[0, 1)$。被高层抽象充分覆盖的底层事件，其在活跃池中的权重将被有效压低，减少与高层摘要的冗余召回。

- 生成局部的均匀随机数 $U_i \in (0, 1)$。
- 计算持久化的确定性采样键：
$$S_i = {U_i}^{\frac{1}{w_{effi}(t)}}$$

**数学结论**：只需在关系型/列式数据库中对 $S_i$ 执行 `ORDER BY S_i DESC LIMIT K`，提取出的 $K$ 条数据即严密等价于"以 $w_{effi}(t)$ 为权重的加权随机概率抽样"。

#### 4.5.2 第二步：异构数据库分层部署

向量数据库无法高效处理复杂的 ORDER BY，因此底层物理拆分为两部分：

- **元数据库（Tier-1, 负责概率过滤与状态）**：采用支持高速索引扫描的关系型数据库（如 PostgreSQL）。建表时将上述的 `sample_key` 设置为核心排序键（Sort Key），使得提取 10 万个高概率召回 ID 的耗时控制在数毫秒级别。同时存储每个事件的累积 $ASF_i$，供离线批处理作业更新复合权重。
- **向量数据库（Tier-2, 负责纯语义检索）**：如 Milvus / Qdrant。仅存储 event_id 与三频段嵌入向量特征（见 §4.4.0），卸载一切标量过滤负担。

#### 4.5.3 第三步：检索引擎的两阶段执行流（Pipeline）

发起 RAG 时，统一频段共振检索被改造为以下两段式防阻塞管线：

- **预取活跃 ID**：系统从 Tier-1 极速拉取（或从缓存直接读取）满足双因子复合权重概率分布的活跃 event_id。实际拉取的数量受 §4.6 PerfMonitor 的在线负载反馈控制，正常负载下拉取完整的 100,000 个；高负荷时则动态收缩（如 20,000 个），始终保证取的是 `sample_key` 最高的头部数据。
- **带限 ANN 检索**：如果向量库支持前置过滤（Pre-filtering），则将这批 ID 列表作为 `HasIdCondition` 传入 Search 接口，配合三频段权重执行混合向量检索；如果不支持，则通过 `GetByID` 批量拉取特征并回退至应用层计算。这使得大模型回忆的物理边界永远只在最符合脑科学规律的活跃记忆内流转。

#### 4.5.4 第四步：离线批处理作业（应对动态遗忘曲线与抽象遮蔽）

因为事件 $w_i$（由最高 importance 角色白描 `effective_forgetting` 派生）随白描时序衰减与 LTP 巩固动态变化，且抽象遮蔽因子 $ASF_i$ 随抽象事件生成而更新，写入时生成的 `sample_key` 将逐渐失效。系统在底层配置了一个异步批处理作业（如 Spark / 独立 Celery 定时任务）：

- 在系统负载低谷（或按特定频率），批量重算库中全量事件：对每个 event_id，按 §1.1.5 规则（基本事件读自身 `role_list`；抽象事件 BFS 展开至叶子后再取）读取最新 `effective_forgetting` 作为 $w_i(t_{now})$，并读取累积遮蔽因子 $ASF_i$。
- 计算复合存活权重 $w_{effi}(t)$，重新生成随机数 $U_i$，批量覆盖更新 Tier-1 数据库的 `sample_key`。
- **快照缓存更新**：作业最后直接执行一次 `SELECT id ... ORDER BY sample_key DESC LIMIT 100,000`，并将结果列表原子性地替换到 Redis 或内存缓存中。
前台 RAG 直接读取这层缓存，从而在保持 $O(1)$ 读取复杂度的同时，完美呈现记忆随时间动态衰减、被抽象逐步遮蔽淘汰的生物学特性。

### 4.6 全局双通道独立耗时监控与自适应降级机制 (Dual-Channel Latency Monitoring)

在 §4.5 通过物理隔离解决了系统基础的 I/O 承载力后，为应对各种复杂交互场景（如强互动的即时对话、高并发群体 NPC 演算），系统必须在"毫秒级及时性"和"后台计算吞吐量"之间保持极端弹性。

为此，系统重构并引入了 rems.observability.PerfMonitor。它不再负责复杂的阈值插值运算，而是专注于对系统核心管线执行双通道的独立耗时监控。两个通道在时间维度上完全解耦、互不干扰。

#### 4.6.1 动态负载因子（Load Factor）计算模型

每个被监控的管线（Phase）都有其设定的健康容忍上限时间（tolerance_ms）。系统持续收集该管线最近 N 次运行的移动平均耗时（rolling_mean）：

$$\text{loadfactor} = \max\left(1.0, \min\left(\frac{\text{rollingmean}}{\text{tolerancems}}, \text{maxloadlimit}\right)\right)$$

当均耗时低于容忍上限时，$\text{loadfactor} = 1.0$，系统处于正常宽裕状态。

当耗时越线时，$\text{loadfactor} > 1.0$，系统进入高负载警告状态，并以此标量直接作为惩罚乘数来缩减候选计算规模。

#### 4.6.2 通道一：回忆链路监控（保障绝对及时性）

该通道实时监控前台直接面对用户的动作，如 rag_search（向量搜索）和 recall_assembly（回忆块组装）。对于交互式应用，回忆提取必须保证在毫秒级闭环。

- **监控目标**：前台 RAG 检索管线。
- **自适应降级动作**：动态收缩 Tier-1 活跃池候选规模。
当该链路出现高负荷（如 load_factor_recall > 1.0）时，下发给向量数据库的预取活跃 ID 数量计算如下：

$$\text{currentcandidates} = \max\left(\text{mincandidates}, \lfloor \frac{\text{basecandidates}}{\text{loadfactorrecall}} \rfloor \right)$$

(例如：基准规模 10 万条，当 load_factor 飙升至 5.0 时，候选池极速收缩至 2 万条。)

**心理学映射**：这等同于在系统面临极度生存压力（高并发、计算过载）时，强制屏蔽冗余信息，只有那些 `sample_key` 排名最顶层、权重最高的核心记忆才有资格参与召回。用生物级的"视野变窄"换取绝对的响应速度。

#### 4.6.3 通道二：抽象演化监控（保障后台吞吐）

该通道独立监控后台离线的沉思与演化动作，如 abstraction_mining（频繁子集挖掘）和 narrative_dedupe（叙事线判重）。由于算法复杂度随抽象规模呈指数/线性增长，这一通道极易堵塞批处理队列。

- **监控目标**：后台归纳推演与查重算法。
- **自适应降级动作**：动态收缩抽象事件的比对窗口。
当该通道监控到耗时越线（如 load_factor_abstract > 1.0）时，系统绝不会去压缩前台的回忆规模（通道隔离），而是专门对后台的挖掘窗口 K 与判重窗口执行线性衰减：

$$\text{K}_{current} = \max\left(\text{mincomparek}, \lfloor \frac{\text{basecomparek}}{\text{loadfactorabstract}} \rfloor \right)$$

(例如：原本需要与最近 200 条抽象进行比对防重，或扫描最近 1000 次回忆进行挖掘，在后台算力报警时，果断将窗口收窄至最近 20 条或 200 次。)

**工程意义**：牺牲小部分老旧数据"重复造轮子"的风险，换取后台队列的畅通无阻，避免因为过度纠结去重或深层挖掘而把整个异步代谢管线压垮。

### 4.7 宏观记忆生命周期补充机制（2026.06 新增）

为应对长周期的系统演化，防止极端情况下的记忆丢失或认知停滞，增加以下三大防御性机制。

#### 4.7.1 深度穿透旁路（Bypass Deep Recall）

当常规活跃子集搜索（受限 Tier-1 候选 + Tier-2 频段共振）的置信度全部低于设定阈值时，触发 Bypass 模式。该机制作为防止低概率确定性记忆（如存折密码、关键日期、一次性的重要指令）永久丢失的最终底线：

- **触发条件**：RAG 返回的 Top-N 结果中，最高相似度得分 < `bypass_confidence_threshold`（默认 0.5）。
- **执行动作**：绕过 Tier-1 的 `sample_key` 限制，无视遗忘因子与抽象遮蔽因子，直接对 Tier-2 向量库发起**全量高精度扫描**。
- **限流保护**：Bypass 调用受独立速率限制（如每分钟最多 1 次），防止被高频触发导致系统雪崩。成功命中后，该条目的 `forgetting_factor` 被强制提升至 `base_forgetting_factor` 的 2 倍以上（重新激活），并重新进入 Tier-1 活跃池。

#### 4.7.2 离线梦境演化（Offline Consolidation）

现有 §3.2 的抽象触发完全依赖于 recall_log 中的被动共现，可能在长周期冷门记忆上产生归纳盲区。离线梦境演化填补了这一缺陷，变被动记忆为主动学习：

- **触发时机**：在系统 I/O 低谷（算力闲置），通过独立调度器触发。
- **数据源**：随机抽取历史事件片段，抽取策略可为：
  - **时间窗随机**：从某个随机时间段内均匀采样；
  - **弱聚类抽取**：对向量库中低置信度聚类边缘的事件进行组合。
- **执行逻辑**：将抽取的事件组强制送入 LLM，要求梳理其中潜在的逻辑关系，尝试生成新的认知图式或概念节点。若 LLM 发现了有效的关系模式，则生成一条特殊的抽象事件，标记来源为 `"origin": "dream"`。
- **防止污染**：梦境产生的抽象事件不写入 `recall_log` 作为频繁项集的统计依据（否则会造成虚假的高支持度），仅参与向量检索与认知问答，其生命周期管理独立于常规抽象。

### 4.8 RagProfile 与混合检索（2026.05）

#### 4.7.3 情感极值免死金牌（PTSD Immunity）

现有 §1.1.3 的摘要熔断与 §1.1.4 的 L1 骨架化在极端情感事件上会造成关键细节的不可逆丢失。情感极值免死金牌机制阻断这一路径，模拟"闪光灯记忆"的永久固化：

- **触发条件**：当基本事件在录入时，任一参与角色的唤醒度 $Arousal > 0.8$（极度恐惧、极度狂喜、创伤性悲伤等极端体验）。
- **保护动作**：该事件被赋予**物理防降级标记**（`ptsd_immune = True`）。系统在所有后续代谢操作中：
  - 禁止对该事件执行 L1 骨架化或超短摘要截断，强制保留最高颗粒度的原始 content_raw；
  - 禁止对该事件执行抽象遮蔽因子的递归下发（即 $ASF_i$ 恒为 0，不受任何上层抽象覆盖），确保其在 Tier-1 活跃池中的权重仅由遗忘因子决定；
  - 该事件的 `base_forgetting_factor` 被强制锁定为 100（永不遗忘），但允许通过 LTP 回忆巩固进一步增强。
- **心理学等价**：复现人类在经历极端创伤或极度喜悦时形成的"闪光灯记忆（Flashbulb Memory）"或"创伤后应激记忆（PTSD）"——事件细节被深刻烙印，难以被时间磨灭或归纳压缩取代。
