# 1610 测试与验收

> 范围：1610–1809｜状态：草稿（回忆重构验收）

## 1. 测试目标

验证 JShi_memory 的回忆实现符合 `design/1010-回忆设计.md`，并保持匠石当前 `MemoryPort` 可调用、返回结果可由薄适配器转换。单元测试使用确定性 hash embedding 和内存 Qdrant，不访问真实模型或网络。

## 2. 测试分层

| 层 | 位置 | 验证内容 | 外部依赖 |
|---|---|---|---|
| 单元 | `tests/unit/` | 范围过滤、索引、排序、预算、遗忘恢复 | SQLite 临时库、Qdrant 内存模式、HashEmbedding |
| 双仓接口 | `tests/integration/test_jshi_recall_contract.py` | 匠石 `MemoryPort` 调用参数和 `RecalledFragment` 转换 | 邻接的 `JShi/src`；不调用模型 |
| 场景 / 在线 | `tests/scenarios/`、`tests/integration/` 其他测试 | 长经历代谢和真实模型效果 | 按各测试门禁启用；不作为单元测试的前置条件 |

## 3. 回忆单元验收矩阵

| 主题 | 验收条件 |
|---|---|
| 材料 | 事件只使用封存摘要；对象事实按对象编号和事件编号保存；无 L1 不退回原文建向量 |
| 线索 | 原始 query 不经模型改写；语义和词面命中信号分开保留 |
| 主体 | 只返回指定 `subject_id` 的材料 |
| 对象 | 显式对象条件限定到该对象事实及关联事件；不连带召回同一事件中其他对象的事实；未传对象不从 query 自动生成硬过滤 |
| 时间 | 显式时间范围与对象条件取交集；按事件发生时间过滤，边界规则由单测固定 |
| 排序 | 对话人对象权重 0.7，其余涉及对象 0.3；排序分为原始相关度 × 对象权重；可及性只在加权分接近时调整顺序 |
| 预算 | 只返回预算容纳的完整表示级别；不截短摘要或原文；对象事实优先于所属事件摘要 |
| 类型 | 结果标明 `event`、`object_event_fact`、`unclosed`；同事件不同类型可并存 |
| 命中副作用 | 返回的记忆可加强可及性；不改原文、摘要或对象事实，不生成回答 |
| 索引 | 事件和对象事实分别索引 L1；L1 与嵌入版本不变时不重复嵌入 |
| 匠石接口 | 接受当前 `MemoryPort.recall` 的 `object_id`、`object_ids`、`interlocutor_object_id`、`level`、`limit`、`anchor_event_ids`，结果可转换为匠石的 `RecalledFragment` |

## 4. 匠石接口边界

匠石当前 `MemoryPort.recall` 提供原始 `query`、多个 `object_ids`、本轮 `interlocutor_object_id`、结果数 `limit`、`level` 和 `anchor_event_ids`。它当前没有结构化 `time_range` 或字符预算参数；因此 `1010` 中的硬时间过滤和总字符预算尚不能由匠石主链路直接传入。查询里的“去年”“上次”仍是普通检索线索，不能视为硬时间范围。

匠石的 `RecallCoordinator` 把全部涉及对象及本轮对话人传给记忆端口。记忆端按说话人 0.7、其余对象 0.3 加权排序；角色标签只表示对象与本轮输入的关系，不表示其在历史记忆中的发言身份。

## 5. 当前待决规则

以下规则在实现前需和 `1010` 一起确认；确认后补成稳定断言：

1. `occurred_at` 缺失时是否使用入库时间。输入契约将空 `occurred_at` 解释为摄入时刻；回忆设计使用事件的 `occurred_at` 过滤。
2. 对象或时间硬过滤开启时，尚未封存句子是否可作为候选，以及如何满足这些硬范围。
3. JShi 的 `level` 如何映射到记忆端的字符预算；当前 JShi 适配器把 `budget` 映射为结果数 `limit`。
4. 对象事实和所属事件是否共享同一个遗忘可及性因子。

## 6. 本地运行

使用独立 Miniconda 环境，Python 3.12：

```powershell
conda env create -f environment-test.yml
conda activate jshi-memory-test
pytest tests/unit -q
pytest tests/integration/test_jshi_recall_contract.py -q
```

双仓接口测试在邻接 `JShi/src` 不存在时会跳过。它只检查 Python 端口和字段转换，不要求启动匠石、LLM 或向量服务。实时模型测试不属于此验收路径。

## 7. 验收完成条件

- `tests/unit` 全部通过；
- 双仓接口测试通过，或在独立环境中因缺少邻接 JShi 仓库明确跳过；
- 第 5 节待决规则已由设计确认，相关测试从待决清单转为固定断言；
- 记录运行环境、命令和结果；不把测试环境依赖于个人 `.env` 或模型缓存。
