# 610 事件封装

> 范围：610–809（子文档可用 620–800）｜状态：已确认（定稿）

## 1. 改动内容

### 1.1 现状（要改掉的）

- `MetabolismService.process_input`：边界检测 → completed / new_unclosed → `seal_event`；80/20 强制分裂；物理红线兜底；残影 / 未完成库；
- `EventService.seal_event`：Enrichment 一次调用产出摘要 + 角色（names_only / full 分支），`CompressionBudget` 做 L1–L10 递归预算；
- 写入路径与回忆、抽象糅合：回忆上下文、`recall_log`、频繁子集挖掘在同一管线；
- `content_raw` 语义由边界检测产出（可能被模型改写 / 补全）。

### 1.2 目标流程（对齐契约）

`ingest_batch` 逐 input 走代谢，内部切分**流程保持不变**，关键约束：

1. **原文保全**：边界切分产出的每个事件 `content_raw` 必须是输入 `text` 的**字面片段**——禁止改写、归一化、补全（单事件场景 `content_raw == text`）；切分机制（边界检测、80/20、物理红线）不变，但提示词与解析层必须输出原文子串；
2. **角色列表 = 主体恒在 + 映射表对象**：`role_list` 恒含主体（subject），并含 `objects` 映射表给出的全部 object_id（与是否说话、是否在文本中出现无关）；**不做 LLM 角色抽取**；
3. **摘要保留多级衰减（已定）**：`summaries` 保留 L1–L10 递归预算与双熔断机制，不做单层简化；契约"先 L1 单层"理解为对外至少保证 L1 可用，内部多级生成照旧；
4. **对象快照**：每个对象生成一句摘要快照（ObjectMemoryEntry 素材，**无情感**——情感只属于主体），供 410 写入对象时间线；
5. **元数据落事件**：`origin`（external / internal / dream，字符串、保留扩展）、`source_ids`、`occurred_at`、`input_id`、`location`（事件要素：时间 / 人物 / 地点）随封存落库；
6. **stored_marks**：`input_id → 本轮封存事件 id 列表`（**封存几个填几个**，按封存顺序）；本轮未封存任何事件（全部留在未完成缓冲）则不写该项、不算错误；`sealed_event_ids` 为批次全部事件；
7. **未完成 / 残影**：维持内部工作缓冲，不跨端口暴露；`unclosed_count` 反映缓冲规模；**字数上限与闲置也构成封存**（程序在边界前强制 `seal_event`）；**边界提示词须配合**：未闭环碎片默认挂 `new_unclosed`，勿滥切 completed；**说话人更换不触发封存**（多人场合合法）；
8. **失败隔离**：批次内逐 input 处理，单个 input 失败进 `errors`，不影响其他 input 与历史。
9. **事件级主体情感**：事件携带匠石情感（8 维 + arousal / valence / energy），由 state 类内容提取；**对象无情感**；情感（arousal）初始化遗忘因子（抗遗忘强度），随时间衰减 → `memory_status`；recall 不新增记录，但**被召回的记忆保留遗忘因子强化**（记忆恢复，符合常理）。

### 1.3 涉及代码

- `pipeline.py`：新增 `ingest_batch` 入口（逐 input 调代谢，聚合 `BackendIngestResult`）；写入路径不再调用回忆 / 抽象；
- `services/metabolism_service.py`：`process_input` 适配——透传 `known_objects`（object_id 集合）与主体；确保边界产物为原文字面片段；
- `services/event_service.py`：`seal_event` 改造——`content_raw` 原样落库；`role_list` = 主体 + 映射对象；L1 单层摘要；对象快照；
- `skills/event_enrichment.py`：去掉角色抽取分支，只产摘要（多级）+ 对象一句快照（无情感）；主体情感单独提取；
- 预算 / 摘要：`CompressionBudget` 保留（L1–L10 多级衰减、弹性浮动、双熔断照旧）；
- 对象时间线更新（410）：封存后按事件追加 ObjectMemoryEntry；
- 删除：写入路径中的角色抽取、`recall_log` 登记、抽象挖掘调用（清单见 1410）。

## 2. 原因

1. **契约原文保全**：`content_raw` 永不改写，验收要求 `content_raw == 输入 text`；
2. **对象来自 01**：不抽取、不建档；角色列表来自映射表 + 主体恒在；
3. **摘要多级衰减（已定）**：保留 L1–L10 递归预算与熔断；契约"先 L1 单层"理解为对外至少保证 L1；
4. **记忆 / 回忆独立**：写入路径不再耦合回忆与抽象；
5. **类人记忆效果**：无主语动作默认归主体；文字未体现的主体 / 对象不丢归属；
6. **内部切分保持不变**：切分流程沿用 REMS3（边界检测、未完成 / 残影、80/20、物理红线），只约束产物为原文字面片段。

## 3. 目标

- 一段输入（切分后）封存为事件，`content_raw` 全部为原文字面片段；
- `role_list` 恒含主体 + 映射表对象；无角色抽取；
- 多级摘要（L1–L10 衰减）+ 对象一句快照（无情感，情感只属主体）；
- `stored_marks` / `sealed_event_ids` / `unclosed_count` / `errors` 语义正确；
- 写入路径无回忆、无抽象残留；`tests/unit` 基线不回归。

## 6. 定稿决策（2026-08-23 确认）

1. **stored_marks**：封存几个填几个（`dict[str, list[str]]`）；部分封存：列表含本轮封存事件，`unclosed_count` 反映残留；完全未封存：不写该项、不算错误（仍在缓冲等后续闭环）；
2. **摘要**：保留 L1–L10 多级衰减（弹性浮动、双熔断照旧）；
3. **对象快照**：无情感；ObjectMemoryEntry = object_id + name + 一句摘要 + 时间（名字用于呈现，与输入映射表一致）；
4. **origin**：按规定 `external / internal / dream`，**保留扩展能力**——字符串字段、不硬校验三值，新值可注册（与 30 侧同步）；legacy `normal` 读取时归一为 `external`；
5. **事件级主体情感**：随事件落库（8 维 + arousal / valence / energy），影响遗忘因子；对象无情感；**回忆加强记忆**（记忆恢复保留）；
6. **activity_id**：本轮不落库（活动相关，30 侧台账用 input_id / stored_marks），schema 预留；
7. **事件要素**：时间（occurred_at / create_time）、人物（object_ids + name）、地点（location，由 enrichment 提取落库）都保留。
8. **未完成封存条件（2026-09-20；提示词对齐 2026-09-21）**：对话常无结局。须 **程序 + 边界提示词** 一起生效：
   - **提示词**：未闭环 / 碎片对话默认进 `new_unclosed`，勿「两句一件」滥切 completed；说话人更换不视为结束；知悉系统会按字数/闲置强制封存，不必提前切碎。
   - **程序**（边界检测之前，单条 UC，非残影总长）：
     - 字数 ≥ `unclosed_char_limit`（默认 2000，`REMS_UNCLOSED_CHAR_LIMIT`）→ 按原文封存；
     - 字数 > `0.5 ×` 上限且闲置 ≥ `unclosed_idle_partial_days`（默认 3 天）→ 封存；
     - 闲置 ≥ `unclosed_idle_hard_days`（默认 7 天）→ 封存；
     - **说话人更换不封存**。
   - 若边界模型仍把未闭环内容大批写入 `completed_events`，程序侧闲置/字数规则几乎不起作用——故提示词与程序缺一不可。
