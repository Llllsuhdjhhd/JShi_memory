# 410 角色系统

> 范围：410–609（子文档可用 420–600）｜状态：草稿（v2：按 000 肃清说明重写，回归简单对象模型）

## 1. 改动内容

### 1.1 现状（要改掉的）

- 角色由 LLM 抽取：RoleExtractionSkill 两阶段（全局前置扫描 + 事件级精确提取），`role_id` 内部生成（`ROL-<uuid>`），维护名字 / 别名；
- 无主体概念：UserMode SINGLE / MULTI、`core_user_role_id`、`active_participants` 做代词消解；
- `RoleService.resolve_and_register` 把抽取结果注册为角色；`update_from_event` 维护白描时间线；EMAEvolver 演化情感；
- 语义卡片已废除；白描时间线含情感、记忆权重、遗忘因子、静默机制。

### 1.2 目标模型（对齐 000 简单输入模型）

- **对象 = 01 object_id 唯一入口**：输入只带 `object_ids`（01 外部对象 id）；无 id 的提及对象**不进 memory input、不建候选**；
- **主体不是对象**：主体就是 `subject_id` 字符串（恒为当前匠石），不建模成 RoleRef，**`subject_id` 绝不放入 `object_id`**（匠石边界）；
- **主体记忆合法**：`object_ids` 为空时，封存事件角色列表可只含主体（匠石侧约定）；
- **对象档案按 object_id 组织**：记忆侧为每个 01 object_id 维护白描时间线与情感（RoleRecord）；名字 / 属性归 01 侧管理（如需展示查 01），记忆后端不再维护名字 / 别名（待讨论 3）；
- **情感与白描保留**：8 维情绪、EMA 演化、白描时间线、遗忘因子、容量与静默机制全部保留（约束 7）。

### 1.3 涉及代码

- `models/role.py`：`role_id` 语义改为 01 object_id（或内部 id + `object_id` 列，待讨论 1）；移除名字 / 别名 / 候选设计；
- `services/role_service.py`：`register / update` 按 object_id 进入；`resolve_and_register` 的 LLM 路径移除；
- `skills/role_extraction.py`：删除（清单见 1410）；
- `services/emotion_service.py`（EMAEvolver）：保留；
- `storage/repository.py`（RoleRepository）：按 01 object_id 读写；
- `config.py`：删除 `user_mode` / `core_user_role_id` / `active_participants`；
- 召回侧引用角色数据的代码**不动**（1010）。

## 2. 原因

1. **000 肃清说明**：对象只有 id（来自 01）；`subject_id` 绝不放入 `object_id`；
2. **约束 3（角色由输入提供）**：与 01 对象体系一致；
3. **约束 7**：角色系统（含情感）完全参照现状；
4. **角色 id 稳定性**：WORK_GUIDE §3.6 指出角色 id 稳定性强烈影响长期记忆质量；LLM 抽取的 `ROL-` id 不稳定且与 01 冲突，必须改为 01 object_id。

## 3. 目标

- 对象档案登记 / 更新闭环基于 01 object_id；
- 主体以 `subject_id` 表达、不混入对象体系；主体记忆（`object_ids` 空）可正常封存；
- 删除 LLM 角色抽取主路径；情感、白描、遗忘全部保留；
- 角色相关 `tests/unit` 按新模型调整并全绿，其余基线不回归。
