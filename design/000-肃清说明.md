# 肃清说明：2XX 输入与对象协议弃用

> 日期：2026-08-21
> 决定：`design/210-输入与对象协议.md` 与 `design/220-记忆分类的理论依据.md` **完全弃用，不保留**。
> 依据：输入应回归简单——记忆输入就是「一段经历原文 + 主体 + 可选对象 + 来源 + 时间」，其余交给 REMS3 现有代谢。

## 一、为什么弃用

1. **过度设计**：四元 `content_type` 分类、六根 / 五蕴框架、`RoleRef`（object_id / name / content / is_subject）、`acquisition_hint`，把本应简单的输入协议复杂化；分类属派生分析，不应在输入端强制。
2. **与匠石契约冲突**：
   - `subject.object_id` 混同主体与外部对象，违反匠石「`subject_id` 绝不放入 `object_id`」的边界；
   - `BackendIngestResult` 缺 `stored_marks` / 消费游标映射，接不上匠石 30 的批次投递与台账。
3. **文本形态下分类轴退化**：当前输入只有文字，「获取方式」轴无数据、无收益。
4. **避免干扰判断**：保留会给后续设计造成有害干扰，弃用更干净。

## 二、替代方案（回归简单）

```python
class MemoryInput:
    subject_id: str                   # 恒为当前匠石
    text: str                         # 经历原文（对话 / 看到 / 感受 / 反思都一样）
    object_ids: tuple[str, ...] = ()  # 01 外部对象；可为空 = 主体记忆
    source_ids: tuple[str, ...] = ()  # 来源链：事实 / 活动 / 认知 id，必带
    occurred_at: datetime | None = None
    input_id: str | None = None       # 30 侧经历段 id，用于回填
    origin: str = "external"          # external | internal | dream，简单标签

class MemoryBatch:
    subject_id: str
    inputs: tuple[MemoryInput, ...]

class BackendIngestResult:
    subject_id: str
    stored_marks: dict[str, str]      # input_id -> sealed event id（30 推进游标用）
    sealed_event_ids: list[str]
    role_ids: list[str] = []          # 本轮登记 / 更新的 01 对象，可为空
    unclosed_count: int = 0
    errors: list[str] = []
```

要点：

- **不做内容分类**；主体就是 `subject_id` 字符串，不建模成 `RoleRef`；
- **对象只有 id**（来自 01），无 id 的提及对象不进 memory input；
- **主体记忆合法**：`object_ids` 可为空，封存时角色列表可只含主体（匠石侧已约定，见 `doc/概念词汇.md`「主体记忆」、`doc/design/09-记忆系统.md` §2.3、`doc/design/30-记忆数据管控.md`）；
- 回忆端口保持 `recall(subject_id, query, *, object_id, level, limit)` 形状，本轮占位不动。
