# cg-301 事件划分提示词

> 目录：`design/refactor/`｜子类：300 更改方案｜状态：草稿（待评审）
>
> 依据：`cg-300`。本文只规定「从连续经验里划出事件、残影和未形成」这一次模型调用：提示词、输出、程序随后做什么。
>
> 本文不改 `prompts.py`，也不改解析和代谢。现有边界提示词在替换之前继续使用。充实、对象白描、主体情感、召回、可及性不在这次调用里。

## 1. 这次调用做什么

模型看到的是已经分好句的连续经验：库里各条残影线，加上本轮新输入。它只判断形成状态，问三个问题：

1. 当前窗口里是否已经有一段自然边界，并且再拆开会把同一段经验切开？是，则这一整段写入 `events`。
2. 这一段是否仍在发展，或局部已经说得通、但后续仍可能属于同一段？是，则整段写入 `residual`。
3. 没有经验结构，也不能完成一条已有线？写入 `no_form`。

形成窗口是进入持久记忆之前的工作空间。残影是窗口里尚未形成独立事件的线：没说完的、还在发展的，以及局部已经闭合但后续仍可能属于同一段的。一条残影里可以同时有多条线。线有程序分配的标识，模型只引用，不新建事件编号。出现次数和字数不参与这三个问题。形成和封存不是同一步。

模型不判断这段值不值得记，不写摘要，不写对象，不写情感，不改写原文，不决定 `seal_reason`。它只标出 `no_form`。程序把这些句子退出工作空间，称为 Dust。过长后的切开、搁置封存、切不开时的封存，由程序在这次调用之外处理。

```text
分句后的残影 + 本轮输入
        │
        ↓
   事件划分（本文）
        │
        ├── events：已经可以独立指认的经验
        ├── residual：形成窗口。没说完的、还在发展的、局部已闭合但后续仍可能同一段的
        └── no_form：没有经验结构，也不能完成一条已有线
        │
        ↓
   程序
        ├── 还原字面原文
        ├── no_form 退出工作空间（Dust），不成为事件
        ├── 续写则接回原线
        ├── 漏掉的句子留待下一轮重判，不写入残影
        └── closed / split / truncated 由程序另定
```

## 2. 输出

只返回 JSON。序号从 1 起，与用户消息里的 `[序号]` 对齐。同一条里的序号按时间排列，可重复出现的句子只写一次。允许用区间 `[起, 止]` 表示连续序号，程序展开。

```json
{
  "events": [
    { "indices": [1, 2, 3], "continues": null }
  ],
  "residual": [
    { "indices": [4, 5], "continues": "R-a1b2" },
    { "indices": [[8, 10]], "continues": null }
  ],
  "no_form": [11, 12]
}
```

| 字段 | 含义 |
|---|---|
| `events` | 已经形成的经验。没有则为 `[]` |
| `events[].indices` | 属于这段经验的句子序号。程序按序号还原字面原文，不采用模型写出的句子 |
| `events[].continues` | 这条事件来自哪条已有残影线。它表示同一经验结构在此形成为事件，不限于字面续写。没有来源线则为 `null` |
| `residual` | 形成窗口里的一条线：没说完、还在发展，或局部已闭合但后续仍可能属于同一段。没有则为 `[]` |
| `residual[].indices` | 这条线现在包含的句子序号 |
| `residual[].continues` | 这条线仍是哪条已有残影线；全新的线为 `null` |
| `no_form` | 没有经验结构、也不能完成一条已有残影线的句子序号。程序让它们退出工作空间，称为 Dust。判断不看出现次数。没有则为 `[]` |

约定：

- 续上某条已有线时，该线里原有句子的序号也要写进同一条 `indices`。程序靠这个知道旧线被接走，避免同一句存两份。
- 已经放进 `events` 的序号，不要再放进 `residual` 或 `no_form`。
- 默认每个句子只属于一处，事件是连续经验上不重叠的区间。只有这句本身同时构成两段已经形成的经验的必要部分时，才可以出现在两条 `events` 里。两段经验都觉得这句有用，不足以重叠。
- 标识只使用用户消息里给出的残影线标识。新线的 `continues` 为 `null`，程序再分配标识。
- 不输出 `seal_reason`、`split_id`、`is_split_prefix`、摘要、对象、情感、重要性或原文句子。`no_form` 只表示未形成经验结构，不表示这段没有价值。

## 3. 系统提示词

下面整段是拟替换现有边界系统提示词的草稿。

```text
你从主体的连续经验中划分已经形成的事件、仍在形成的残影线，以及没有经验结构的句子。

事件是从连续经验中形成的一段相对独立、内部一致、具有自然语义边界的经验。它记下当时发生在「我」身上的事、我感知到的、我被告知的。缺少结局不妨碍它成为事件。判断的是这一段能否作为一个整体存在，不是句子在句法上是否完整，也不是它有多少句。

核心原则：在不破坏独立性的前提下，用尽可能少的事件覆盖连续经验。取当前窗口里保持内部一致的最大区间。已经有自然边界的，写入 events。这一段显然还在继续的，整段留在 residual，不要把已经说得通的前缀先标成事件。字数由程序处理，你不看字数。

已形成、尚未封存的单元在用户消息里单独列出。它们已经是事件。新句子若属于同一经验，写入 events，continues 填该标识，indices 含该单元原有序号。不要把这些单元改写入 residual。

残影是形成窗口。里面可以有多条线：明显没说完的，还在发展的，以及局部已经闭合、但后续仍可能属于同一段的。每条线有程序给出的标识。出现次数不参与判断。

你不做这些事：
- 不判断这段经历是否重要、是否值得保存。
- 不写摘要，不提取对象，不写情感，不解释动机，不改写原文。
- 不因为字数、闲置或「应该结束了」而切开或封存。过长时的切开、搁置后的封存，由程序处理。
- 不发明封存原因，不发明分裂编号。

划分规则：

1. 语义边界优先。在仍然内部一致的前提下，取尽可能长的一段作为一条事件。这是核心原则。三句话可以是一条事件，只要它们是同一段经验。同一段还在继续时，整段留在残影，不要拆成多条短事件。
2. 后句依赖前句时，前句必须在同一段里。代词、省略的主语、「然后」「所以」「但是」等衔接，都不能把被指向的句子留在段外。单独读这段时，要能知道主语是谁、承接的是什么。
3. 短而连续的动作收成一段。属于这段的环境句、当时的感受句，和这段写在一起，不要单独剩在残影里。
4. 说话人更换、多人交替，本身不构成边界。仍是同一段经验就放在一起；已经是另一段经验就另成一条线或另一条事件。
5. 话题短暂岔开后回到原线的，不要因此拆开。岔开的内容若是另一段独立经验，单独成线。
6. 不要求事件有完整结局。「刚才小王给我打电话。」「小王让我明天过去。」都可以是事件。「我明天准备去上海出差，因为」经验已经开始，还不能独立指认，留在残影。
7. 还不能作为一段独立经验被指认的，留在残影。承诺未兑现、问题未回答、动作未做完，只在因此还不能指认这段经验时才留在残影。
8. 没有经验结构、也不能完成一条已有残影线的句子放入 no_form。没有上下文的「好的」「嗯」「是的」属于这种。它若把某条残影线形成为事件，与该线一起放入 events。它若接上一条已经开始的经验，放入该线的 residual。不要因为这句以后也许会有用，就放进 residual。
9. 交错的几段经验分成几条线，不要揉成一条。例如一边商量周末、一边问晚饭，是两条线。
10. 结果来自某条已有残影线时，填写 continues 为那条线的标识，并把该线原有句子的序号写进同一条 indices。对 events，这表示该线在此形成为事件。对 residual，这表示仍是同一条正在形成的经验。没有来源线则为 null。
11. 不要因为一条线很长就自行按比例切开。整条仍是一段未完成的经验时，整段放进 residual。
12. 只返回句子序号，不返回句子原文。

输出严格 JSON，格式见用户消息。
```

## 4. 用户提示词

占位由程序填入。残影线列表为空时写「（无）」。序号表由程序分句后生成，并标明哪些序号属于哪条已有线、哪些是本轮新输入。

```text
## 已形成、尚未封存
{formed_lines}

这些标识只可写入 events 的 continues。没有则本节为（无）。

## 已有残影线
{residual_lines}

每条线的标识只可原样写入 continues。没有列出的标识不要发明。

## 句子
{range_hint}
{indexed_input}

句子序号从 1 开始。已有残影线的句子在前，本轮新输入的句子在后。区间含义见上一行。

## 输出
{
  "events": [
    { "indices": [1, 2, 3], "continues": null }
  ],
  "residual": [
    { "indices": [4, 5], "continues": "R-xxxx" },
    { "indices": [8, 9], "continues": null }
  ],
  "no_form": []
}

indices 可写成单个序号的列表，或含区间的列表，例如 [1, [4, 6], 8]。
同一条记录内按时间排列。
来自某条已有线时，该线原有序号与新句子序号写在同一条 indices 里。continues 表示结果来自哪条线。
没有事件、没有残影线或没有未形成的句子时，对应数组为 []。
只返回这一段 JSON。
```

`residual_lines` 的每一行形如：

```text
- R-a1b2：序号 1–2
- R-c3d4：序号 3
```

线上不标注滚动次数。形成状态不由出现次数决定。

`range_hint` 只标出哪些序号属于已有残影、哪些属于本轮输入，是输入结构，不参与经验判断。例子：

```text
（【1..4】=已有残影；【5..7】=本轮新输入）
```

`indexed_input` 的例子：

```text
[1] 我们商量周末出门。
[2] 还没定哪天。
[3] 晚饭吃什么？
[4] 刚才小王给我打电话。
[5] 那就周六。
```

## 5. 程序在模型返回之后做什么

这一节是运行时行为。

1. 按序号还原字面原文。模型写出的句子一律不用。
2. `continues` 指向一条已有残影线时：用该线的原文接上本段里新增的句子，然后删除该线。落在该线原有序号上的句子不再拼接第二次。
3. `continues` 为 `null` 的 `residual` 成为新的残影线，程序分配标识。
4. 旧线的句子若已全部出现在 `events`、`residual` 或 `no_form` 里，删除该旧线。
5. `no_form` 中的句子退出工作空间，记为 Dust。不写成事件，不留在残影里，不参与召回。可另存时间与原文作审计，该记录不是记忆。
6. 三个数组都没有领走的句子，留待下一轮重新划分。不写成残影线，不记为 Dust，不封成事件。残影只接收模型标成正在形成的经验。
7. `events` 中不是程序切开的前段，先量还原后的原文字数。资源目标（`event_min_chars`，常见工作尺度约 800–1000 字，可调，鼓励偏长）只决定是否立刻做完整封存，不参与形成判断，也不是事件的语义尺度。达到的，封存原因记为 `closed`。达不到的仍然是事件，可在形成窗口多留一些时间等待持久化，不改标成残影，不再送回划分去问它是不是事件。下一轮新句子若属于同一经验，模型把它扩进这条事件。系统必须结束等待时，按已有边界封存，原因记为 `closed`。模型不看这个字数。
8. 单条残影线超过处理长度时，程序另一次调用切开：在相对收束处分成前段和后段。前段封存，原因记为 `split`，并用前缀链连着后段。后段留在残影。切不开、且该线已经是一段没说完的经验，则整条封存，原因记为 `truncated`。这次划分调用不负责这一步。
9. `no_form` 退出为 Dust，永远不封成事件。已经形成、尚未封存的事件在必须结束等待时直接封存，原因记为 `closed`。仍在残影里的线先再划分一次：模型给出事件则封为 `closed`，仍未形成则封为 `truncated`，标成 `no_form` 的退出为 Dust。过长切开的前段记 `split`。封存之后不把多条事件再合并。
10. 封存之后才做表示、主体情感、对象白描、索引和向量。这些步骤对一条事件做一次。模型输出 `no_form` 序号，不写「Dust」或封存原因。

同一句被两条 `events` 使用时，两条事件各保留这句原文。这句不再留在残影里。这种重叠只用于该句同时构成两段经验的情形，不作为常规写法。

## 6. 例子

例子供评审和以后放进提示词时选用。提示词正文若过长，优先保留例 1、例 2、例 4、例 5、例 6。

### 例 1　没有完整结局，也可以是事件

句子：`[1] 刚才小王给我打电话。`

这次调用里只有这一句，也没有迹象表明同一段经验还要继续，可以形成事件。若同一窗口里还有「他说项目延期。」「我决定修改计划。」则收成一条，不把第一句先封出去。

```json
{
  "events": [{ "indices": [1], "continues": null }],
  "residual": []
}
```

### 例 2　还没说完，留在残影

句子：`[1] 我明天准备去上海出差，因为`

```json
{
  "events": [],
  "residual": [{ "indices": [1], "continues": null }]
}
```

### 例 3　单独的应答不够形成事件

已有残影：无。句子：`[1] 好的。`

没有上下文时，它没有经验结构，也没有一条残影线可以靠它完成。放入 `no_form`。程序让它退出工作空间，不留在残影，也不封成事件。

```json
{
  "events": [],
  "residual": [],
  "no_form": [1]
}
```

### 例 4　应答把已有线说完

已有线 `R-a1b2` 为序号 1。句子：`[1] 周六见吗？` `[2] 好的。`

```json
{
  "events": [{ "indices": [1, 2], "continues": "R-a1b2" }],
  "residual": []
}
```

### 例 5　交错的两条线

已有线 `R-a1b2` 为序号 1–2，`R-c3d4` 为序号 3。

```text
[1] 我们商量周末出门。
[2] 还没定哪天。
[3] 晚饭吃什么？
[4] 那就周六。
[5] 晚饭想吃面。
```

周末这条被说完。晚饭这条仍在形成，并接上原来的线。这个例子测的是交错时的指代和话题恢复，基本定义不依赖它。

```json
{
  "events": [{ "indices": [1, 2, 4], "continues": "R-a1b2" }],
  "residual": [{ "indices": [3, 5], "continues": "R-c3d4" }]
}
```

### 例 6　指代不能拆开

```text
[1] 小王说明天要出差。
[2] 他让我替他看一下邮件。
```

`他` 指向小王。两句在同一条事件里。

```json
{
  "events": [{ "indices": [1, 2], "continues": null }],
  "residual": []
}
```

### 例 7　环境和感受跟着这段走

```text
[1] 我们在路口站了很久。
[2] 当时风很大。
[3] 我有点累。
[4] 最后还是决定先回家。
```

```json
{
  "events": [{ "indices": [1, 2, 3, 4], "continues": null }],
  "residual": []
}
```

### 例 8　说话人更换仍是同一段

```text
[1] 甲：周末去哪儿？
[2] 乙：还没想好。
[3] 甲：那我们再看看。
```

```json
{
  "events": [],
  "residual": [{ "indices": [1, 2, 3], "continues": null }]
}
```

若第 3 句已经是另一件事，例如「对了，晚饭吃面」，则 `[1, 2]` 留在原线，`[3]` 进入另一条 `residual`，`continues` 为 `null`。

这三条一起仍是一段没说完的经验，所以留在残影，不放入 `no_form`。以后若没有后续、工作空间又必须清出它，封存为事件，原因是 `truncated`，而不是 Dust。

### 例 9　很长也不在这次调用里切开

一条已有线加上新句子后仍然是同一段未完成的经验，即使序号很多，也整段放进一条 `residual`，`continues` 指向原线。不按比例切成前段事件和后段残影。

### 例 10　没写到的句子

模型漏了序号 6。程序把序号 6 留到下一轮重新划分。不把它写成残影线，也不把它记为 Dust。

## 7. 和现有实现的对应

替换代码时再改名。现在的字段先留着。

| 现有输出 | 本文 |
|---|---|
| `completed_events` | `events` |
| `content_raw_indices` | `indices` |
| `continuation_of` | `continues` |
| `new_unclosed` | `residual` |

## 8. 这次不写进提示词的事

- 表示的层数和字数预算。
- 每个对象一句事实、主体情感。
- 召回是否交还残影。
- 休眠经验在什么条件下重新可及。
- 角色分级、三级快照、肖像、抽象和演化。
- 立即封存的资源目标（常见工作尺度约 800–1000 字，可调，鼓励偏长；旧 200 字作废），以及处理长度、延迟和压力何时结束等待。这些是持久化参数，不进入形成判断。模型只输出 `no_form` 序号；Dust 这个名字由程序使用。
