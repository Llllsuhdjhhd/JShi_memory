# cg-300 记忆模型收口

> 目录：`design/refactor/`｜子类：300 更改方案｜状态：草稿（待评审）
>
> 概念依据：`my_idea/talk_with_gpt.md` 全文。这次落地的是记忆侧：Subject、Experience、Residual、Event、Object 的经历关联、Representation、事件的长期变化、Recall 的交还。长期特征、当前状态、互动倾向、巩固、反思和梦境属于匠石，只保留存储和占位。
>
> 事件怎么形成、怎么封装，参照原项目 `my_idea/1 basic_event.md` 与 `my_idea/4 recall.md` §4.1–§4.2。不采用原项目的召回算法、抽象事件、角色戏剧分级、残影改写和无主句子删除。
>
> 与已定稿的关系：批次端口、主体恒在、对象身份来自外部映射、原文为字面片段，仍按 `design/210`、`design/410`、`design/610`。本文只改记忆侧与概念文档冲突的形成规则和对象在封存时的写法。思考、反思、梦境、巩固由匠石承担，本仓不实现、不改匠石。`consolidate` / `dream` 继续占位，存储上留出以后写入的位置。召回管线本次不改：不改候选、打分、精排和返回结构。

## 1. 一次改动要完成的结构

本仓只做记忆：保存「我」的经历，形成事件，维护表示、对象关联和可及性，并在被取用时把已有内容交还。思考、反思、梦境、多条经历形成认识，都属于匠石。本仓不实现这些步骤，也不修改匠石。

```text
本仓
  经历 → 残影 → 三个出口形成事件 → 表示 → 挂上对象 → 可及性变化
  召回时交还已保存的事件、对象关联、表示和时间
匠石（本仓不动）
  取走上述内容 → 思考 / 反思 / 梦境 → 若要写回，使用预留入口
```

预留是指：长期特征、当前状态、互动倾向在存储里留有位置；`consolidate` 与 `dream` 保持现有占位，不在这次改成会思考的实现。匠石尚未写回时，这些位置为空，召回按空交还。

写入路径不调用召回，也不生成抽象事件。图数据库、向量库、关系数据库只提供保存和查找，不规定什么叫事件、什么叫对象。

## 2. 主体与经历

主体是「我」，在本仓即匠石。`subject_id` 不放入对象标识。

经历是连续进入记忆的信息。本轮输入仍是一批原文，带主体、可选对象映射、来源和时间。记忆不按对话、阅读、传感器做分类。一段里没有点名的对象，只要映射表里有，就挂到由此形成的事件上。对不上的指称留在原文里，不新建对象。

## 3. 事件

事件是残影中一段能够相对独立成立的经验。边界取处理能力允许范围内、尽可能长的一段语义闭环。不按固定时间、固定字数或固定句数切分。事件不等于世间那件尚未结束的事。

形成分两步：先找最长闭环（单独读得通；后句依赖前句时前句必须在内），再看是否达到最小规模。像「好的」这样的话留在残影里。

| 出口 | 条件 | 结果 | `seal_reason` |
|---|---|---|---|
| 自然闭环 | 最长闭环，且达到最小规模 | 一条事件 | `closed` |
| 资源 | 一条线长到无法继续处理 | 能切开就切开；切不开就封存已有内容 | 前段 `split`；切不开为 `truncated` |
| 搁置 | 一条线超过时限没有后续 | 按当时字面原文封存 | `truncated` |

`truncated` 不是自然结束。`split` 的各段用前缀链保持可追溯。

### 3.1 写入步骤

`ingest_batch` 的合并、失败隔离和 `stored_marks` 不变。说话人更换不封存。残影不另存一份可改写的草稿：库里是 `UnclosedEvent`，视图由它们的原文拼接。

```text
新经历并入残影
  → 搁置超过时限的线：truncated
  → 边界检测（只回句子序号，把残影和新输入划完）
        → 够格的闭环：closed
        → 过长的线：相对收束处切开，前段 split，后段留在残影并记下前缀
        → 续写并回已有的线
        → 没有任何序号领走的句子：收成一条未完成线留下
  → 仍超过处理上限且无法切开：truncated
  → 表示，并给每个对象写一句事实白描
  → 若新事件的对象正连着休眠事件，提高那些事件的可及性
```

每一轮按序号把整段划完。已经被划进事件或新未完成线的旧线从库里删除，避免同一段原文留两份。没被任何序号领走的句子不删除、不改写，收成一条未完成线。残影只因封存而变短。`force_save` 若保留，原因记为 `truncated`。

### 3.2 从原项目封装保留的步骤

- 未完成线与残影视图、`continuation_of` 续写（原 §4.1）。
- 句子序号，本地还原字面原文（原 §4.2.1）。短而连续的动作收成一段；强指代不拆开；属于这段的环境句、情绪句一并选入（原 §4.2.2 的向上吸收）。
- 过长时在相对收束处切开，前段约七到九成；评估失败则再切一次，修复结果不再评估；前缀链双向记下（原 §4.2.4、§4.2.5、§1.1.9）。这是资源出口内部的重试，不是另一套规则。
- 先定边界，再做表示（原 §4.2.3 的两步）。不使用其中的角色抽取模式。
- 摘要预算递减、短文本放宽、说完一个意思可略超预算、再压会成残句就停止（原 §1.1.3 的熔断）。不要求写满十层。

不采用残影改写、无主句子物理删除、封存时按字数截断原文。

### 3.3 封存时写入的事件字段

| 字段 | 写法 |
|---|---|
| `content_raw` | 序号还原的字面片段。续写则为旧线原文加本轮片段 |
| `seal_reason` | `closed` / `split` / `truncated` |
| `summaries` | 动态层数。`split` 与 `truncated` 只写本段已出现的内容 |
| 前缀链、后继链 | 仅 `split` 维护 |
| 主体 | 恒在 |
| 对象 | 映射表中的对象全部挂上，不分级、不带情感 |
| 对象白描 | 每个对象一条，绑 `event_id`，用「我」的视角写这一次发生了什么。禁止长期性格 |
| 主体情感 | 只从本段原文提取。唤醒程度设定 `forgetting_factor` 初值。对象无情感 |
| `ptsd_immune` | 极端唤醒时为真，原文不在写入时降级 |

装饰、洞察、抽象字段不填。`is_abstract` 保持为假。不再写 `l1` / `l2` / `l3` 三套快照，封存路径不调用人物肖像。

### 3.4 相对本仓形成流程要改的行为

| 现有行为 | 收口后 |
|---|---|
| 边界前按字数或闲置封存，且不记原因 | 闲置走搁置出口并记 `truncated`。过长先切开，不在边界前整段封存 |
| 多套结束条件并列 | 只判断是否超过处理长度、是否超过搁置时限。现有配置继续用作这两个数值 |
| 未复述的旧线整段删除 | 已划走的旧线删除；没被任何序号领走的句子收成一条未完成线留下 |
| 残影改写、残影截尾 | 删除。总长越限时对整条线做 `truncated` |
| `seal_event` 截断原文 | 删除 |
| 充实产出三级白描、装饰、肖像 | 摘要、主体情感，以及每个对象一句事实白描 |
| 边界提示词把结束交给强制封存 | 改为寻找最长闭环；低于最小规模留在未完成；过长则切开并声明配对 |

## 4. 表示

表示只属于事件，是同一原文的不同分辨率：较完整的描述、较短的摘要、核心事实、极简说法。层数停在「再压就损失关键意义」。原文和已生成的各层都保留。

各层在封存时一次写好。召回怎样选用哪一层，本次不改。极端唤醒的事件保留原文，供以后取用。

单条事件的压缩到此为止。多条事件形成的稳定认识不写进 `summaries`。

## 5. 对象

对象是与「我」发生关系的实体。身份只用外部给的 `object_id` 和名字。记忆不抽取、不建档、不分级。

对象上与概念文档对应的五块里，本仓这次只落实前三块。后两块留出追加记录的表结构（时间、正文、`source_event_ids`），不写生成逻辑，也不在封存时填入。

| 部分 | 这次谁写入 | 存储 |
|---|---|---|
| 基本信息 | 本仓，来自映射表 | `object_id`、名字。不另写小传 |
| 与我的经历 | 本仓，封存时写一句事实白描 | 每个对象、每条事件一条，绑 `event_id`。只写这一次发生了什么，不写长期性格 |
| 重要事件 | 本仓，由可及性筛出 | 查询条件，不另存一份名单 |
| 长期特征 | 匠石以后写回 | 表留空。追加、墓碑的字段先在，没有写入接口的实现 |
| 当前状态 | 匠石以后写回 | 同上。有记录时，时间最新的一条视为当前 |

封存时为每个映射对象追加一条白描：`event_id`、一句以「我」叙述的事实。不再写三级快照，也不调用 `PortraitService.note_event`。长期特征、当前状态、互动倾向不从这句里生成。已有的墓碑标记保持可用：匠石若把某条写回标成墓碑，召回排除它，原文仍在。本仓不判断哪条认识该被更正。

## 6. 互动倾向

互动倾向是对象上单独的一层，表示「我」倾向于怎样与这个对象相处。它不从单条事件的摘要或情感直接算出，本仓也不推算。

存储上与长期特征相同：预留按时间追加的记录（正文、`source_event_ids`、墓碑位）。这次不提供填充它的实现。匠石以后写入时，旧记录保留，更正用墓碑。

主体在某次事件里的情感仍只属于那条事件，用来设定该事件的遗忘初值，不写入倾向。

## 7. 长期变化

这次落实的长期变化只作用在事件上。原文不删。写回记录的可及性以后与事件同一套规则，表结构里留下 `forgetting_factor` 一类字段，这次不对其做衰减或强化。

| 变化 | 何时 | 做什么 |
|---|---|---|
| 形成 | 事件封存 | 可及性初值来自主体唤醒 |
| 强化 | 召回命中 | 提高该事件的可及性，允许超过初值。沿用现有召回命中后的提高 |
| 衰减 | 读取事件时按距上次使用的时间计算 | 可及性下降。去掉肖像疲态这条并行规则 |
| 休眠 | 可及性低于现有静默阈值 | 普通召回默认不取出。事件仍在 |
| 再激活 | 新经历封存时，其对象与休眠事件的对象相同 | 把这些休眠事件的可及性抬到阈值之上。不改写原文，不新生成摘要 |

经历后来不同，由新的事件按时间留下，旧事件靠衰减沉下去。哪一条认识记错了，由匠石标墓碑。本仓不比较两条经历是否冲突。

## 8. 巩固、反思与梦境

巩固、反思和梦境属于匠石。本仓不挖掘频繁项集，不生成抽象事件，不在写入时归纳，也不实现「想完再写回」的过程。

`consolidate` 与 `dream` 维持现在的占位：调用不产生事件、不产生对象认识、不改匠石。仓库里已有的做梦技能继续不接入。

可能性留在三处，供匠石以后使用，这次都不填内容：

- 对象的长期特征、当前状态、互动倾向表。
- 事件的 `origin` 已能标 `internal`。匠石若把一段它产生的文字当作新经历送进 `ingest_batch`，走与外部经历相同的形成过程。
- 召回结果里为上述写回预留空字段。有记录时原样交还，没有则为空。

## 9. 召回

召回是认知向记忆来取。本次不改召回代码：候选、打分、精排和返回结构保持现状。`seal_reason`、一句白描和空着的长期认识表先落在写入侧，召回以后再读。

## 10. 落地顺序

1. 事件增加 `seal_reason`，形成流程按第 3 节收束。充实改为摘要、主体情感和每个对象一句事实白描，去掉三级快照、装饰和肖像。
2. 残影按序号整段重划。没被领走的句子留下。去掉改写和截尾。
3. 为长期特征、当前状态、互动倾向建空表。不接写入实现。`consolidate` 与 `dream` 保持占位。召回不改。
4. 新经历封存后，若对象与休眠事件相同，只在事件字段上提高可及性，不进召回管线。
5. 边界提示词改为第 3.4 节的口径：划分整段残影，寻找最长闭环，过长则切开。

## 11. 验收

- 交错经历能分成多条线；续写并回原线；「好的」留在残影；过长产生 `split` 和前缀链；超时和切不开为 `truncated`，摘要不写结局。
- `content_raw` 是字面片段。没被任何序号领走的句子仍在未完成库。已划走的旧线不重复保留。写入不调用召回，不产生抽象事件，不改写残影。
- 每个对象有一句绑在该事件上的事实白描，其中没有长期性格。不写三级快照。长期特征、当前状态、互动倾向三张表存在且为空。`consolidate` 与 `dream` 被调用时不写事件、不写对象认识。召回管线行为不变。
- 已标墓碑的记录不被普通召回取出，原文仍在。本仓不新增墓碑判断。
- 召回管线不改。同一对象的新事件在封存时把此前休眠的相关事件可及性抬高，原文不改写。
- 极端唤醒事件的原文仍在，不在写入时被截断或降级。
