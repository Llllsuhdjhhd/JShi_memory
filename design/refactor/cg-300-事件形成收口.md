## 1. 记忆保存什么

本仓只做记忆：保存「我」的经历，形成事件，维护原文、表示、对象关联和可及性，并在被取用时把已有内容交还。思考、反思、梦境、多条经历形成认识，都属于匠石。本仓不实现这些步骤，也不修改匠石。

```text
经历
  → 残影（工作态：事件正在形成的工作空间）
       继续形成
       或形成事件（持久态：原文、表示、对象关联、可及性）
       或进入 Dust（已退出工作空间，不是记忆）
  → 召回：交还已保存的事件
  → 匠石：思考 / 反思 / 梦境；若要写回，使用预留入口
```

`closed`、`split`、`truncated` 是事件上的 `seal_reason`，说明封存时发生了什么。它们不是三种事件。

残影不是低一级的事件。事件形成完成之前，经验停在残影里；封存之后，它成为事件。Dust 不是事件，也不进入召回。

预留是指：长期特征、当前状态、互动倾向在存储里留有位置；`consolidate` 与 `dream` 保持现有占位。匠石尚未写回时，这些位置为空。

写入路径不调用召回，也不生成抽象事件。图数据库、向量库、关系数据库只提供保存和查找。它们不规定什么叫事件、什么叫残影、什么叫对象。

## 2. 主体与经历

主体是「我」，在本仓即匠石。`subject_id` 不放入对象标识。

经历是连续进入记忆的信息。本轮输入仍是一批原文，带主体、可选对象映射、来源和时间。记忆不按对话、阅读、传感器做分类。一段里没有点名的对象，只要映射表里有，就挂到由此形成的事件上。对不上的指称留在原文里，不新建对象。

## 3. 事件

事件是从连续经验中形成的一段相对独立、内部一致、具有自然语义边界的经验。它记下当时发生在「我」身上的事、我感知到的、我被告知的，并带上来源、时间和主体情感。记忆保存「我经历过什么」。一段经历里听到的话，仍是这段经历的原文；本仓不把它改写成关于世界的判断，也不比较两条经历哪一条更真。

形成的目标是：在不破坏独立性的前提下，用尽可能少的事件覆盖连续经验。事件是当前窗口里能够保持内部一致的最大区间。有自然边界就形成事件；这一段还在继续就留在残影。三句话可以是一条事件，例如「小王给我打电话，说项目延期，我决定修改计划。」十句仍属同一段闲谈的，收成一条，不收成十条。不按固定句数开窗口，也不在封存之后把多条事件再合并。

形成和封存是两步。形成只问这段是不是已经有自然语义边界。封存才问现在要不要为它做表示、白描、情感、索引和向量。模型不看字数。200 字是封存门槛，起点用这个数：达到的当轮封存，原因是 `closed`；达不到的仍然是事件，留在形成窗口里等待持久化，不退回残影，也不再参加一轮「它还是不是事件」的判断。

下一轮若新句子属于这同一段经验，模型把它扩进这条已形成的事件。扩到 200 字就可以封存。系统必须结束等待时，已形成的事件按原边界封存，原因是 `closed`；仍在残影里、没有自然边界的，封存原因是 `truncated`。不设固定轮数。短原文封存后保留原文，不再强行另写一层归纳。

### 3.0 封存原因

`seal_reason` 写在已经形成的事件上。

| 原因 | 封存时发生了什么 | 事件本身 |
|---|---|---|
| `closed` | 在处理能力内形成了一段相对独立、内部说得通的经验 | 一条事件 |
| `split` | 一条连续经验太长，在相对收束处切开。前段封存，后段留在残影，两边用前缀链相连 | 前段仍是一条正常事件。切开只说明它从更长的经验里分出来 |
| `truncated` | 这段没有因语义闭环而结束，仍按当时字面原文封存 | 一条事件。摘要只描述已经出现的内容 |

`truncated` 只用于已经具有经验结构、但因生命周期或处理能力无法完整留下的线。现在都记这一个原因，不再拆成更细的字段：

- 一条仍在形成的线必须离开工作空间，始终没有后续，也没有自然闭环。
- 一条线已经超过处理上限，又找不到可以切开的相对收束处。

没有独立经验结构的句子不走 `truncated`。它们按下一节退出。

`split` 的前段用前缀链连着后段。后段后来若再封存，继承这条链。

### 3.0.1 形成状态与退出

划分只判断形成状态，问三个问题：

1. 当前窗口里是否已经有一段自然边界，并且再拆开会把同一段经验切开？是，则这一整段成为事件。不要把其中已经局部说得通的前缀单独封出去。
2. 这一段是否仍在发展，或局部已经说得通、但后续仍可能属于同一段？是，则整段留在残影。
3. 没有经验结构，也不能完成一条已有线？标为 `no_form`。

形成窗口是连续经验进入持久记忆之前的工作空间。残影是窗口里尚未形成独立事件的线：明显没说完的，例如「我明天准备去上海出差，因为」；还在发展的；局部已经闭合、但后续仍可能属于同一段的。已经形成、尚未达到封存门槛的事件也留在这个窗口里，身份仍是事件。不另设候选事件。没有上下文的「好的」没有经验结构，标为 `no_form`，不进入残影。出现次数和字数都不参与形成判断。

程序把 `no_form` 退出工作空间，称为 Dust。Dust 是工作空间的退出结果，不属于记忆本体。记忆本体是事件、残影、表示、对象关联和可及性。Dust 不写成事件，不留在残影里，不参与召回。它可以留下时间与原文供事后查看，那份记录不是记忆。

残影离开工作空间时只有事件这一条记忆出口：

```text
残影
  ├── 形成完成 → 事件（closed）
  ├── 过长切开 → 前段事件（split）+ 后段残影
  └── 必须清出、经验仍在 → 事件（truncated）

no_form → Dust
         不进入事件
```

`truncated` 只用于已经在残影里的未完成经验。没有经验结构的句子不走 `truncated`。模型不写 Dust，也不决定封存原因。工作空间何时必须清出，是程序的生命周期参数，不改变上面三个问题。现有实现仍会把搁置超时的线一律封成 `truncated`。这和本节不一致，留待以后改。代码这次不动。

### 3.1 写入步骤

`ingest_batch` 的合并、失败隔离和 `stored_marks` 不变。说话人更换不封存。残影不另存一份可改写的草稿：库里是 `UnclosedEvent`，视图由它们的原文拼接。

```text
新经历并入残影
  → 搁置超过时限的线：现有实现一律 seal_reason = truncated
    （模型上：已是没说完的经验才 truncated；从未形成经验的线应进入 Dust，见 3.0.1，代码尚未区分）
  → 边界检测（只回句子序号，把残影和新输入划完）
        → 够格的闭环：seal_reason = closed
        → 过长的线：相对收束处切开，前段 seal_reason = split，后段留在残影并记下前缀
        → 来自已有线的，接回该线或形成为事件
        → 未形成：退出为 Dust，不写入残影
        → 模型漏掉的句子：留待下一轮重判
  → 仍超过处理上限且无法切开：seal_reason = truncated
  → 表示，并给每个对象写一句事实白描
  → 现有实现会在对象相同且旧事件休眠时提高可及性（见第 7 节；这不是模型规则）
```

每一轮按序号划分。已经被划进事件、残影或 Dust 的旧线从库里删除，避免同一段原文留两份。模型漏掉的句子留待下一轮重判，不改写。未形成的句子不进入残影。`force_save` 若保留，只对已经在残影里的经验记为 `truncated`。

### 3.2 从原项目封装保留的步骤

- 未完成线与残影视图、`continuation_of` 续写（原 §4.1）。
- 句子序号，本地还原字面原文（原 §4.2.1）。短而连续的动作收成一段；强指代不拆开；属于这段的环境句、情绪句一并选入（原 §4.2.2 的向上吸收）。
- 过长时在相对收束处切开，前段约七到九成；评估失败则再切一次，修复结果不再评估；前缀链双向记下（原 §4.2.4、§4.2.5、§1.1.9）。切开失败后再试一次，仍记在同一次封存里。
- 先定边界，再做表示（原 §4.2.3 的两步）。不使用其中的角色抽取模式。
- 摘要预算递减、短文本放宽、说完一个意思可略超预算、再压会成残句就停止（原 §1.1.3 的熔断）。不要求写满十层。

不采用残影改写、无主句子物理删除、封存时按字数截断原文。

### 3.3 封存时写入的事件字段

| 字段 | 写法 |
|---|---|
| `content_raw` | 序号还原的字面片段。续写则为旧线原文加本轮片段 |
| `seal_reason` | `closed` / `split` / `truncated` |
| `summaries` | 动态层数。`split` 与 `truncated` 只写本段已出现的内容 |
| 前缀链、后继链 | 仅 `split` 维护 |
| 主体 | 恒在 |
| 对象 | 映射表中的对象全部挂上，不分级、不带情感 |
| 对象白描 | 每个对象一条，绑 `event_id`，用「我」的视角写这一次发生了什么。禁止长期性格 |
| 主体情感 | 只从本段原文提取。唤醒程度设定 `forgetting_factor` 初值。对象无情感 |
| `ptsd_immune` | 极端唤醒时为真，原文不在写入时降级 |

装饰、洞察、抽象字段不填。`is_abstract` 保持为假。不再写 `l1` / `l2` / `l3` 三套快照，封存路径不调用人物肖像。

### 3.4 相对本仓形成流程要改的行为

| 现有行为 | 收口后 |
|---|---|
| 边界前按字数或闲置封存，且不记原因 | 闲置封存并记 `truncated`。过长先切开，不在边界前整段封存 |
| 多套结束条件并列 | 只判断是否超过处理长度、是否超过搁置时限。现有配置继续用作这两个数值 |
| 未复述的旧线整段删除 | 已划走的旧线删除。模型漏掉的句子留待下一轮重判，不写成残影线，也不封成事件 |
| 残影改写、残影截尾 | 删除。总长越限时对整条线做 `truncated` |
| `seal_event` 截断原文 | 删除 |
| 充实产出三级白描、装饰、肖像 | 摘要、主体情感，以及每个对象一句事实白描 |
| 边界提示词把结束交给强制封存 | 改为三个形成状态：已形成、正在形成、未形成。残影只收正在形成的经验。未形成退出为 Dust。过长则切开并声明配对 |

## 4. 表示

表示只属于事件，是同一原文的不同分辨率：较完整的描述、较短的摘要、核心事实、极简说法。换一层表示，这条经验仍是同一条。原文和已生成的各层都保留。表示、对象白描、情感和索引都在封存后对这一条事件做一次。形成阶段少封装一条，这些步骤就少做一轮。原文已经很短时，不再强行再压一层。

层数、每层字数和熔断阈值是工程参数。模型只要求：层数停在「再压就损失关键意义」，不把某一固定层数写成记忆的常量。现有实现沿用动态层和已有预算，不要求写满十层。

各层在封存时一次写好。召回怎样选用哪一层，本轮不改。极端唤醒的事件保留原文，供以后取用。

单条事件的压缩到此为止。多条事件形成的稳定认识不写进 `summaries`。

## 5. 对象

对象是与「我」发生关系的实体。身份只用外部给的 `object_id` 和名字。记忆不抽取、不建档、不分级。

对象上与概念文档对应的五块里，本仓这次只落实前三块。后两块留出追加记录的表结构（时间、正文、`source_event_ids`），不写生成逻辑，也不在封存时填入。

| 部分 | 这次谁写入 | 存储 |
|---|---|---|
| 基本信息 | 本仓，来自映射表 | `object_id`、名字。不另写小传 |
| 与我的经历 | 本仓，封存时写一句事实白描 | 每个对象、每条事件一条，绑 `event_id`。只写这一次发生了什么，不写长期性格 |
| 重要事件 | 本仓，由可及性筛出 | 查询条件，不另存一份名单 |
| 长期特征 | 匠石以后写回 | 表留空。追加、墓碑的字段先在，没有写入接口的实现 |
| 当前状态 | 匠石以后写回 | 同上。有记录时，时间最新的一条视为当前 |

封存时为每个映射对象追加一条白描：`event_id`、一句以「我」叙述的事实。例如经历是「小明今天告诉我他准备辞职」，白描只写这一次他告诉了我这件事。它不写成「小明是一个敢于冒险的人」。后一句要等多条经历之后，由匠石形成认识。

不再写三级快照，也不调用 `PortraitService.note_event`。人物肖像是「我现在认为这个对象是什么样」，属于匠石，不进入记忆本体。`1010` 里已有的肖像实现保持为旧工程，不在本模型里当作对象记忆。长期特征、当前状态、互动倾向不从这句白描里生成。

已有的墓碑标记保持可用：匠石若把某条写回标成墓碑，召回排除它，原文仍在。本仓不判断哪条认识该被更正。两条互相不一致的经历都保留。

## 6. 互动倾向

互动倾向是对象上单独的一层，表示「我」倾向于怎样与这个对象相处。它不从单条事件的摘要或情感直接算出，本仓也不推算。

存储上与长期特征相同：预留按时间追加的记录（正文、`source_event_ids`、墓碑位）。这次不提供填充它的实现。匠石以后写入时，旧记录保留，更正用墓碑。

主体在某次事件里的情感仍只属于那条事件，用来设定该事件的遗忘初值，不写入倾向。

## 7. 可及性

可及性是一条已经保存的经验，在当前时刻被重新取回的难易程度。它与原文、表示、对象关联并列，属于这条事件。原文一直在。变的是现在好不好把它取出来。低于阈值后进入休眠，经验仍在，普通召回默认不取出。

衰减、召回命中后提高、休眠，都是可及性的现有实现，落在 `forgetting_factor` 和静默阈值上。本轮不新增遗忘规则，也不定义再激活的机制。下一阶段要问的是：什么会使一条休眠经验重新变得可及。对象相同只说明两段经历涉及同一个对象，不能推出旧经验应当一起重新可及。

写回记录的表里留有同类字段。这次不对写回记录做衰减或强化。

| 现有实现 | 何时 | 做什么 |
|---|---|---|
| 初值 | 事件封存 | 由主体唤醒设定 |
| 提高 | 召回命中 | 提高该事件的可及性，允许超过初值 |
| 下降 | 读取事件时按距上次使用的时间计算 | 可及性下降 |
| 休眠 | 低于现有静默阈值 | 普通召回默认不取出。事件仍在 |
| 同对象抬高 | 新事件封存，且与某条休眠事件对象相同 | 代码里会把那些休眠事件抬到阈值。这只是现有实现，不写入本模型的再激活定义。不改写原文，不新生成摘要 |

经历后来不同，由新的事件按时间留下，旧事件的可及性可以下降。哪一条认识记错了，由匠石标墓碑。本仓不比较两条经历是否冲突。

## 8. 巩固、反思与梦境

巩固、反思和梦境属于匠石。本仓不挖掘频繁项集，不生成抽象事件，不在写入时归纳，也不实现「想完再写回」的过程。

`consolidate` 与 `dream` 维持现在的占位：调用不产生事件、不产生对象认识、不改匠石。仓库里已有的做梦技能继续不接入。

可能性留在三处，供匠石以后使用，这次都不填内容：

- 对象的长期特征、当前状态、互动倾向表。
- 事件的 `origin` 已能标 `internal`。匠石若把一段它产生的文字当作新经历送进 `ingest_batch`，走与外部经历相同的形成过程。
- 召回结果里为上述写回预留空字段。有记录时原样交还，没有则为空。

## 9. 召回

召回是认知向记忆来取已保存的内容。候选、打分、精排用哪一种检索，属于实现，不进入记忆本体。换检索方式不改变本文的模型。

残影要不要被召回交还，本轮不定，也不改代码。现有实现会把相关未完成并进召回结果。定稿时只在下面两条里留一条：

- 召回只交还事件。残影始终留在内部工作空间。
- 召回可以交还未完成，但结果里必须标明它仍是工作态，尚未成为事件。

在这条定下来之前，不要把「残影不交还」写成已经生效的契约。

## 10. 落地顺序

1. 事件增加 `seal_reason`，形成流程按第 3 节收束。充实改为摘要、主体情感和每个对象一句事实白描，去掉三级快照、装饰和肖像。
2. 残影按序号整段重划，只保留正在形成的经验。未形成的句子退出为 Dust。去掉改写和截尾。
3. 为长期特征、当前状态、互动倾向建空表。不接写入实现。`consolidate` 与 `dream` 保持占位。召回不改。
4. 同对象抬高休眠事件的可及性只留在现有代码里，不写成模型规则。
5. 边界提示词改为第 3.4 节的口径：划分整段残影，寻找最长闭环，过长则切开。

## 11. 验收

- 交错经历能分成多条线；一条事件来自某条残影线时写明该线。没有经验结构的「好的」标为未形成并退出为 Dust，不留在残影，不封成事件。仍在形成的线过长产生 `split` 和前缀链；必须清出的未完成经验为 `truncated`，摘要不写结局。
- `content_raw` 是字面片段。模型漏掉的句子留待下一轮重判。已划走的旧线不重复保留。写入不调用召回，不产生抽象事件，不改写残影。
- 每个对象有一句绑在该事件上的事实白描，其中没有长期性格。不写三级快照。长期特征、当前状态、互动倾向三张表存在且为空。`consolidate` 与 `dream` 被调用时不写事件、不写对象认识。召回管线行为不变。
- 已标墓碑的记录不被普通召回取出，原文仍在。本仓不新增墓碑判断。
- 同一对象抬高休眠事件可及性只作为现有实现存在，原文不改写。它不作为再激活的模型规则。
- 极端唤醒事件的原文仍在，不在写入时被截断或降级。
