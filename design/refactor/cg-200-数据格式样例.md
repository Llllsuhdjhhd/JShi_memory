# cg-200 数据格式样例

> 目录：`design/refactor/`｜子类：200 数据格式｜状态：草稿（待评审）
>
> 用途：给出**一段简单匠石对话**从写入到回忆的各级真实格式（进来的、内部中间态、出去的、落库的），
> 作为端口契约与仓储字段的对照样例，也可直接改写成 golden 断言。
>
> 依据代码：`src/rems/port.py`、`pipeline.py`、`services/metabolism_service.py`、
> `services/event_service.py`、`services/recall_budget.py`、`recall/pipeline.py`、`storage/repository.py`。
> 相关设计：`design/210`（输入协议）、`410`（对象时间线）、`610`（事件封装）、`810`（存储）、`1010`（回忆）。

## 0. 示例前提

30 侧已经切好两个经历段：

```text
阿明: 明天早上八点老地方见，我带上那张唱片。
匠石: 好，我记着了，别再迟到。
```

设定：主体 `jshi-main`；对象映射 `{"阿明": "OBJ-AMING-01"}`；两条段同属活动 `ACT-2026-0906-01`；
边界模型判定这段对话语义闭环，封存为 **1 个**事件。

本文所有 id、时间、分数均为示意值。

---

## 1. 记忆侧

### 1.1 进来：`MemoryBatch`（30 → 后端）

```json
{
  "subject_id": "jshi-main",
  "experiences": [
    {
      "subject_id": "jshi-main",
      "text": "阿明: 明天早上八点老地方见，我带上那张唱片。",
      "objects": {"阿明": "OBJ-AMING-01"},
      "interlocutor": "OBJ-AMING-01",
      "source_ids": ["ACT-2026-0906-01", "FACT-8831"],
      "occurred_at": "2026-09-06T21:12:00",
      "segment_id": "SEG-000123",
      "origin": "external"
    },
    {
      "subject_id": "jshi-main",
      "text": "匠石: 好，我记着了，别再迟到。",
      "objects": {"阿明": "OBJ-AMING-01"},
      "interlocutor": null,
      "source_ids": ["ACT-2026-0906-01"],
      "occurred_at": "2026-09-06T21:12:20",
      "segment_id": "SEG-000124",
      "origin": "external"
    }
  ]
}
```

| 字段 | 语义 | 约束 |
|---|---|---|
| `subject_id` | 归属主体（匠石），恒在 | 绝不放进 `object_id` |
| `text` | 经历原文，含说话人前缀 | 不归一化、不改写、不切分（切分是后端内部事） |
| `objects` | 名字/称呼 → 01 `object_id` | 含没说话的、没出现的；空表 = 主体记忆 |
| `interlocutor` | 本段**说话/互动对象**，与 `objects`（泛提及）分开 | 主体自述 / 系统段为 `null` |
| `source_ids` | 来源链（事实 / 活动 / 认知 id） | 契约必带；缺失该段进 `errors` |
| `occurred_at` | 经历发生时间 | 空 = 摄入时刻 |
| `segment_id` | 30 侧经历段 id | `stored_marks` 靠它回填游标 |
| `origin` | `external` / `internal` / `dream` | 字符串保留扩展；legacy `normal` 归一为 `external` |

### 1.2 内部中间态：批级分装

`ingest_batch` 先把整批合成**一段**输入再走代谢（不是逐段各跑一次），并自建 `sub_segments`：

```json
{
  "subject_id": "jshi-main",
  "text": "阿明: 明天早上八点老地方见，我带上那张唱片。\n\n匠石: 好，我记着了，别再迟到。",
  "objects": {"阿明": "OBJ-AMING-01"},
  "source_ids": ["ACT-2026-0906-01", "FACT-8831", "ACT-2026-0906-01"],
  "segment_id": "SEG-000123+SEG-000124",
  "origin": "external",
  "interlocutor": "OBJ-AMING-01",
  "sub_segments": [
    {"segment_id": "SEG-000123", "text": "阿明: …", "objects": {"阿明": "OBJ-AMING-01"}, "interlocutor": "OBJ-AMING-01"},
    {"segment_id": "SEG-000124", "text": "匠石: …", "objects": {"阿明": "OBJ-AMING-01"}, "interlocutor": null}
  ]
}
```

- 轮次之间用**空行**连接；`segment_id` 用 `+` 连接、`source_ids` 取并集、`interlocutor` 取**首个非空段**。
- `sub_segments` 有两个用处：封存时按事件内容归属对象（避免整批对象并集串扰）、回填事件级 `interlocutor`。

### 1.3 出去：`BackendIngestResult`（后端 → 30）

```json
{
  "subject_id": "jshi-main",
  "stored_marks": {
    "SEG-000123": ["EVT-3f9c1a..."],
    "SEG-000124": ["EVT-3f9c1a..."]
  },
  "sealed_event_ids": ["EVT-3f9c1a..."],
  "role_ids": ["OBJ-AMING-01"],
  "unclosed_count": 0,
  "errors": []
}
```

- `stored_marks`：`segment_id → 本轮封存事件 id 列表`。封存几个填几个；**一个事件横跨多段则多段都记**；
  本轮完全没封存（全留在未完成缓冲）**不写该项、不算错误**。
- `role_ids` 只作回传，**匠石不得据此建档**。
- `unclosed_count` 只反映后端内部缓冲规模（非端口暴露物）。

```json
  "summaries": {"L1": "阿明约匠石明早八点老地方见面并带唱片，匠石应下。", "L2": "…", "L3": "…"},
  "summary_lengths": {"L1": 24, "L2": 0, "L3": 0},

    {
      "role_id": "jshi-main",

  ],
  "emotion": {
    "emotion": {"anger": 0.0, "fear": 0.0, "joy": 0.2, "sadness": 0.0,
                 "surprise": 0.0, "disgust": 0.0, "trust": 0.3, "anticipation": 0.4},
    "arousal": 0.4, "valence": 0.3,
    "rolling_arousal": 0.4, "rolling_valence": 0.3, "energy": 0.4
  },

  "forgetting_factor": 0.87,
  "origin": "external",
  "status": "active",
  "is_tombstoned": false,
  "is_abstract": false,
  "ptsd_immune": false,
  "source_ids": ["ACT-2026-0906-01", "FACT-8831", "ACT-2026-0906-01"],

  "recall_metadata": {
    "keywords": ["老地方", "唱片"],
    "location": "老地方",
    "interlocutor": "OBJ-AMING-01"
  },

  "split_successor_event_ids": [],
  "decoration": null,
  "insight": null,
  "abstract_coverage": 0.0
}
```

格式要点：

- **原文保全**：`content_raw` 只做 `len_msg`（默认 2000 字）截断，不改写；单事件场景等于输入 `text`。
- **主体恒在**：`role_list[0]` 恒为主体（`role_id = subject_id`、`importance = "S"`）；
  对象按 `objects` 映射表挂载，**与文本是否提及无关**；`objects` 空时 `role_list` 只含主体，合法。
- **对象无情感、无等级**：对象条目的 `emotional_model` 全 0，`importance` 固定 `"C"`（仅作占位）。
- `forgetting_factor = 2^(gain × (AE − 0.5))`，`gain = recall_activation_gain = 2.0`：
  arousal 0.4 → `2^(-0.2) ≈ 0.87`（低于中性 1.0 → 衰减更快）；中性 0.5 → 1.0。
- `interlocutor` 不在顶层列，走 `recall_metadata` JSON 落库（免 schema 迁移）；
  `location` 顶层列与 `recall_metadata.location` 是同一份数据的两处落点。
- 抽象字段（`is_abstract` / `is_abstracted` / `abstraction_level` / `source_events` / `abstract_coverage`）
  **仍在表上但恒为默认值**：属遗留，清理见 `design/1210` / `1410`。

### 1.5 落库：`white_painting_entries`（对象白描，1 行）

对象线真正的活数据。对象**不建 `roles` 行**，白描行直接以 `role_id = object_id` 存在：

```json
{
  "id": 1,
  "subject_id": "jshi-main",
  "role_id": "OBJ-AMING-01",
  "event_id": "EVT-3f9c1a...",
  "role_summary": "阿明提醒匠石别迟到。",
  "l1_mention": "阿明约匠石明早老地方见。",
  "l2_interaction": "阿明提醒匠石别迟到。",
  "l3_decision": "阿明决定带唱片赴约。",
  "emotional_model": {"emotion": {"...": 0.0}, "arousal": 0.0, "valence": 0.0,
                       "rolling_arousal": 0.0, "rolling_valence": 0.0, "energy": 0.0},
  "importance": "C",
  "create_time": "2026-09-06T21:12:31",
  "memory_weight": 0.0,
  "forgetting_factor": 1.0,
  "base_forgetting_factor": 1.0,
  "last_accessed_time": "2026-09-06T21:12:31",
  "is_suspicious": false
}
```

- `role_summary` 取 `l2_interaction or l1_mention or l3_decision`（记忆路径固定该优先序）。
- 三个 `l1/l2/l3` 由 enrichment 在**这一段事件原文**上产出（设计称"匠石对对象的分级白描"），事件关联可溯源。

### 1.6 落库：`stored_marks`（台账，2 行）

```json
{"subject_id": "jshi-main", "input_id": "SEG-000123", "event_ids": ["EVT-3f9c1a..."], "created_at": "2026-09-06T21:12:31"}
{"subject_id": "jshi-main", "input_id": "SEG-000124", "event_ids": ["EVT-3f9c1a..."], "created_at": "2026-09-06T21:12:31"}
```

纯台账，**不含游标状态**：30 侧凭它自维护 `memory_start`。

### 1.7 不写的表 / 写入的向量

| 目标 | 行为 | 说明 |
|---|---|---|
| `roles` | **不写** | 对象不建档（不建角色系统） |
| `object_memory_entries` | **不写**（表保留） | 对象线改由 `white_painting_entries` 承担；回忆的"对象路"仅在 `role_list` 未命中时回退查它 |
| `unclosed_events` / `shadow` | 视情况写 | 内部缓冲；本例已闭环，`unclosed_count = 0` |
| `recall_traces` | 写入时无关 | 只在回忆侧写 |
| Qdrant | 写 1 点 | 见下 |

```json
{
  "id": "<md5(event_id) 十六进制>",
  "vector": ["…嵌入向量…"],
  "payload": {
    "event_id": "EVT-3f9c1a...",
    "subject_id": "jshi-main",
    "object_ids": ["OBJ-AMING-01"],
    "create_time": 1786000000.0
  }
}
```

**索引文本不是原文**，而是检索文本：

```text
阿明约匠石明早八点老地方见面并带唱片，匠石应下。
对象:OBJ-AMING-01
地点:老地方
```

即 `L1 摘要 + 对象 id + 地点`（富化嵌入，`design/1010 §2.4`）；原文只在最终展示时给出。

## 2. 回忆侧

### 2.1 进来：调用签名

```python
recall(
    subject_id="jshi-main",
    query="阿明约我什么时候见面",
    object_id="OBJ-AMING-01",   # 焦点对象（匠石侧传当前说话者）
    level=1,
    limit=None,
    anchor_event_ids=(),
)
```

- `query` 保持原文（后端做归一化与规则意图分类，不改写语义）。
- `object_id` 可空：空 = 跨对象（含主体记忆）。
- `anchor_event_ids` 会连同其 `split_prefix_event_ids` 前缀链一起拉入候选。

### 2.2 出去：`tuple[RecalledFragment, ...]`

只命中本例事件时：

```json
[
  {
    "event_id": "EVT-3f9c1a...",
    "text": "阿明: 明天早上八点老地方见，我带上那张唱片。\n\n匠石: 好，我记着了，别再迟到。",
    "content": "阿明约匠石明早八点老地方见面并带唱片，匠石应下。",
    "kind": "external",
    "object_id": "OBJ-AMING-01",
    "interlocutor": "OBJ-AMING-01",
    "source_ids": ["ACT-2026-0906-01", "FACT-8831", "ACT-2026-0906-01"],
    "score": 0.0176,
    "summary_level": "L6",
    "occurred_at": "2026-09-06T21:12:00"
  }
]
```

若缓冲里还有一句**同一说话人**没说完的话，它会作为第一条一起返回：

```json
[
  {
    "event_id": "UC-9a1c2f",
    "text": "阿明: 那张唱片其实…",
    "content": "阿明: 那张唱片其实…",
    "kind": "unclosed",
    "object_id": "OBJ-AMING-01",
    "interlocutor": "OBJ-AMING-01",
    "source_ids": [],
    "score": 90.0,
    "summary_level": "raw",
    "occurred_at": "2026-09-06T21:20:05"
  },
  { "event_id": "EVT-3f9c1a...", "comment": "同上例" }
]
```

若该对象已积累出人物肖像且预算分配开启，肖像条目会排在最前：

```json
{
  "event_id": "portrait:OBJ-AMING-01",
  "text": "…肖像最长级文本…",
  "content": "…同上…",
  "kind": "portrait",
  "object_id": "OBJ-AMING-01",
  "interlocutor": "OBJ-AMING-01",
  "source_ids": [],
  "score": 100.0,
  "summary_level": "L6",
  "occurred_at": "2026-09-06T22:00:00"
}
```

格式要点：

| 字段 | 语义 | 注意 |
|---|---|---|
| `text` | 原文（`content_raw`） | 契约溯源字段；未完成条目为挂起原文 |
| `content` | 按档位取出的展示文本 | 受预算截断（`used` 长度） |
| `kind` | `external` / `internal` / `dream` / `unclosed` / `portrait` | 事件取 `origin` |
| `object_id` | "主对象"近似（role_list 中 importance 最高的非主体） | 泛提及，**不用于软纠偏** |
| `interlocutor` | 说话/互动对象 | **软纠偏依据**（1.15 增益 / 0.90 惩罚，缺一即 1.0） |
| `score` | 排序用融合分 | **不同 kind 不同量纲**：肖像 100、未完成 90（同对象）、事件 ≈ RRF×衰减 |
| `summary_level` | 档位标签 / `raw`（未完成） | 见 §3 待对齐点 1 |

事件分数量纲（示意）：

```text
rrf    = 1 / (rrf_k 60 + 通道内排名 1)      = 0.01639
eff    = event_fatigue 1.0 × forgetting_factor 0.87 × 0.5^(age_days/60) ≈ 0.87
score  = rrf × eff^factor_alpha 0.5 × 情感调制 1.0 × 对象归属 1.15 ≈ 0.0176
```

### 2.3 附带落库：`recall_traces`（每次 recall 一行，观测用）

```json
{
  "recall_id": "b1e7f0…",
  "subject_id": "jshi-main",
  "query": "阿明约我什么时候见面",
  "object_id": "OBJ-AMING-01",
  "level": 1,
  "limit": null,
  "anchor_event_ids": [],
  "created_at": "2026-09-06T22:01:10",
  "n_items": 1,
  "items": [
    {
      "event_id": "EVT-3f9c1a...",
      "object_id": "OBJ-AMING-01",
      "interlocutor": "OBJ-AMING-01",
      "score": 0.0176,
      "summary_level": "L6",
      "source_ids": ["ACT-2026-0906-01", "FACT-8831", "ACT-2026-0906-01"],
      "text": "阿明: …",
      "content": "阿明约匠石明早八点老地方见面并带唱片，匠石应下。",
      "occurred_at": "2026-09-06T21:12:00"
    }
  ]
}
```

- 由 `recall_trace_enabled`（默认 true）控制；`recall_trace_max_items`（默认 60）截断条目数。
- **只作观测**：不参与抽象、不影响召回结果；写失败只告警。
- 这是核对"这条记忆属于谁"（诊断张冠李戴）的主要载体。

### 2.4 预算受限的回忆块：`assemble_recall_block(...)`

```json
{
  "items": [
    {
      "event_id": "EVT-3f9c1a...",
      "object_id": "OBJ-AMING-01",
      "interlocutor": "OBJ-AMING-01",
      "kind": "external",
      "level": "L6",
      "budget": 3200,
      "used": 24,
      "content": "阿明约匠石明早八点老地方见面并带唱片，匠石应下。",
      "score": 0.0176
    }
  ],
  "total_length": 24,
  "budget": 20000
}
```

数字来源（默认配置，`context_window = 88000`、`chars_per_token = 1.5`）：

| 量 | 公式 | 默认值 |
|---|---|---|
| `context_chars` | `context_window × chars_per_token` | 132000 |
| `len_msg` | `context_chars / 66` | 2000 |
| `physical_redline` | `context_chars × 10 / 66` | 20000 |
| `safe_watermark` | `context_chars × 2 / 66` | 4000 |
| 回忆档位 | `L1=100`，逐级 `×2`，共 6 级 | L1=100 … **L6=3200** |
| 肖像触发 | `context_window / 600` | 146 字 |

## 3. 字段 → 落库位置速查

| 端口字段 | 落库位置 |
|---|---|
| `subject_id` | `events.subject_id`、`stored_marks.subject_id`、`white_painting_entries.subject_id` |
| `text`（原文） | `events.content_raw`（截断到 `len_msg`） |
| `objects`（map） | `events.role_list[*].role_id`（非主体条目） |
| `interlocutor` | `events.recall_metadata.interlocutor`；`unclosed_events.interlocutor` |
| `source_ids` | `events.source_ids`（JSON list） |
| `occurred_at` | `events.occurred_at`（`create_time` 另存摄入时刻） |
| `segment_id` | `events.input_id`、`stored_marks.input_id` |
| `origin` | `events.origin` |
| 摘要 | `events.summaries` / `summary_lengths` / `actual_max_level` |
| 主体情感 | `events.emotion`（顶层）+ `events.activation_energy` |
| 遗忘因子 | `events.forgetting_factor` |
| 对象白描 | `white_painting_entries`（`role_id = object_id`） |
| 检索文本 | Qdrant point 的 `vector` + `payload` |

## 4. 待对齐点

1. **`summary_level` 标签与 `content` 文本来源不一致**：预算分配是"能装最高级就装最高级"，
   短文本会被标成 `L6`；但 `content` 文本是在管线里按 `level` 参数（默认 1）选出的 **L1** 文本，
   仅被截到该档预算。样例里 `summary_level: "L6"` 配 L1 摘要即此现象——
   也是 `tests/unit/test_recall_trace.py::test_recall_persists_query_and_items` 当前失败的原因。
   二选一：要么 `content` 按所选档位重新取文本，要么 `summary_level` 保留真实取用档位（推荐后者 + 另加 `allocated_level`）。
2. **未完成条目是否跨端口，文档未统一**：本样例中的 `kind: "unclosed"` 片段会从 `recall` 返回，
   但 `design/210 §5/§6` 与 `610 §1.2(7)` 仍写"不跨端口暴露"，只有 `1010 §8.2` 改成了新说法。
3. **`score` 量纲不统一**：事件分（≈0.01–0.03）与肖像（100）、未完成（90）不可比；
   若上层要按分数做阈值判断，需要统一或另给 `score_kind`。
4. **`unclosed` 片段的 `source_ids` 为空**：未完成条目在缓冲里不保存来源链，
   若 30 侧要凭回忆结果回溯来源，需要补 `source_ids` 到 `unclosed_events`。
5. **`location` 双落点**：顶层 `location` 列与 `recall_metadata.location` 重复，建议明确定哪一处为准。

## 5. 可直接改写成 golden 断言的检查点

- 单事件场景：`event.content_raw == experience.text`（原文保全）。
- `role_list[0].is_subject is True` 且 `role_id == subject_id`（主体恒在）。
- `objects` 的每个 value 都出现在 `role_list` 的非主体条目里（含未在文本出现的对象）。
- `set(result.stored_marks) == {seg.segment_id for seg in valid}`，且并集等于 `sealed_event_ids`。
- `object_memory_entries` 与 `roles` 在本路径**零新增行**。
- `recall` 返回的每个片段 `text` 都能在对应 `events.content_raw`（或 `unclosed_events` 原文）中找到。
- `interlocutor` 从 ingest → `events.recall_metadata` → `RecalledFragment` → `recall_traces.items` 全程一致。
- 焦点对象一致者的排序优于冲突者，且冲突者**仍被返回**（软纠偏有界、不硬删）。
