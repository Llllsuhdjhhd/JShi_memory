# 10 总体设计与主体模型

> 范围：10–209（子文档可用 20–200）｜状态：已确认（定稿）

## 1. 改动内容

本部分是全部改造的总纲，具体改动按章节拆分：

- **主体模型**：确立"只有一个主体：匠石"，删除 REMS 原有的多角色 / 多用户（UserMode SINGLE/MULTI）概念
- **类人记忆效果**：匠石的记忆应产生与人类记忆类似的效果——以自我（主体）为中心、主体恒在；输入文字未体现主体或对象时，归属以"主体恒在 + 对象映射表"为准，不因文字缺省而丢失归属
- **常理原则**：设定须符合常理——recall 不新增记忆记录（不写新事件、不登记 recall_log），但**回忆会加强记忆**：被召回的记忆强化遗忘因子（记忆恢复，符合人类记忆规律）；遗忘随时间衰减，记忆只降可见性、不删原文；失败不污染历史
- **输入模型（回归简单）**：输入 = 经历原文 + `subject_id` + 可选 `objects` 映射表 + `source_ids` + 时间，不做内容分类（详见 210）
- **流程拆分**：把 `REMSPipeline.ingest` 的单线流程拆成两个独立端口——**记忆（写入）**与**回忆（读取，先阙如）**
- **范围裁剪**：只删除抽象（详见 1210、1410）；**做梦与回忆的代码保留不动**（本次不开发，不删除、不修改）
- **信念修正（墓碑）**：保留墓碑标记作为显式修正机制（`is_tombstoned` + insight 审计前缀），**不删原文、只降可见性**；冲突检测延后到 1010
- **接入契约**：对齐匠石《记忆层契约》的 MemoryBackendPort 四步端口——`ingest_batch`（本轮实现，含 `stored_marks` 供 30 侧推进游标）、`recall` / `consolidate` / `dream`（占位不动）；对象由输入映射表（名字 / 称呼 → 01 object_id）提供

## 2. 原因

对应匠石的需求约束：

1. 主体只有一个匠石——REMS 的多主体 / 多用户模式与匠石架构冲突；
2. 回忆与记忆是两件独立的事——现状把两者糅合进同一条 ingest 线，必须拆开；
3. 对象由输入提供——输入带对象映射表（名字 / 称呼 → 01 object_id，含没说话的），后端不抽取、不建档、不建角色系统；
4. 主体恒在——`subject_id` 显式（恒为当前匠石），且 `subject_id` 绝不放入 `object_id`（匠石边界）；
5. 主体记忆（无对象）合法——`objects` 可为空，封存时角色列表可只含主体；
6. 事件封装完全参照现状——但事件长度、强制封装细节待讨论（见 610）；
7. 对象时间线参照现状（摘要快照、遗忘）；**情感只属于主体（匠石）且为事件级**——事件携带匠石情感（8 维 + arousal / valence / energy），对象无情感；**情感影响遗忘因子**；
8–9. 回忆、做梦本次不开发，但**代码保留不动**——这两块独立于当前改造，后续需要单独认真设计（接口、数据结构、与记忆侧的关系都未定），本轮不删除、不修改，保留原样作为后续设计输入；
10. 抽象删除（本轮唯一删除项）；
11. 无关内容尽量删除——仅限与抽象相关的代码。

## 3. 目标

- 单主体记忆后端：输入（经历原文 + `subject_id` + 可选 `objects` 映射表 + `source_ids` + 时间）→ 事件 / 对象时间线持久化；
- 记忆 / 回忆两个独立端口，互不耦合（回忆代码保留，但不参与记忆写入路径）；
- 只删除抽象相关代码；做梦、回忆代码原样保留；测试基线不回归。

## 4. 与其他模块的关系

- 210 输入协议：输入 = 经历原文 + 主体 + 可选对象 + 来源 + 时间（详见 210）；

- 1010 回忆 / 1210 做梦与抽象：预留或删除，划定边界；

## 5. 预留的功能

- MemoryBackendPort 双端口形状（`ingest_batch` / `recall`）；
- schema 的 `subject_id` 作用域（当前恒为单个主体值，为将来每个匠石独立实例预留）；
- 回忆、做梦的现有代码原样保留（独立块，后续单独设计，见 1010）；
- 抽象删除后的回补路径见 1210。

## 6. 定稿决策（2026-08-23 确认）

1. **事件长度与强制封装**：内部切分流程保持不变（边界检测、80/20、物理红线照旧），610 已定；
2. **source_ids**：可多值、必带；缺失时该 input 进 errors、不封存（210 已定）；
3. **未知名字**：保持原样、不返回候选（410 已定）；
4. **信念修正 / 墓碑**：**保留墓碑标记**（`is_tombstoned` + insight 审计前缀）作为显式修正机制，不删原文、只降可见性；冲突检测与回忆相关，延后到 1010；
5. **向量索引**：本轮占位不写，回忆启用时重建（810 已定）；
6. **写入路径与回忆**：拆分后写入路径不再调用回忆 / 抽象（610 已定）；回忆实现细节在 1010。
